# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A browser car-maneuvering trainer (parking simulator) — one self-contained file, `index.html` (~5700 lines): CSS, HTML UI, and a single `<script>` with zero dependencies, no build step, no package.json; git-репозиторий на `main` без feature-веток (плюс генерат `codegraph-src/index.js` для индекса — см. Code Search). All UI text and code comments are in Russian — keep new text and comments in Russian. Testing harness: the headless demo regression (`computeIdealPath` runs on every `loadLevel` — intercept `console.warn` over all `DEMOS` keys, zero timeouts = green) plus `learner.js` (см. ниже) for the teaching texts.

### Перед деплоем — коммит и пуш (обязательно)

На сервер уезжает ровно то, что лежит в репозитории. Деплой из грязного дерева кладёт на прод код,
которого нет в git: его не воспроизвести, не отревьюить и не откатить. Все ручные деплой-скрипты
проверяют это сами и падают до первой заливки — грязное дерево или неотправленные коммиты
останавливают деплой. Аварийный обход `SKIP_GIT_GUARD=1` оставляет предупреждение в логе.
Деплой через GitHub Actions это правило соблюдает по построению: CI собирает из запушенного коммита.

## Проверки: сценарии и мутации

Два гейта поверх существующих инструментов. Оба поставлены по образцу проекта
load-calculator, но собраны заново: там опорой служили pytest-bdd, vitest, Stryker и mutmut,
а здесь нет ни тест-раннера, ни `package.json` — только stdlib Node и `playwright-core` из
`PW_DIR`.

**Сценарии** (`specs/features/**/*.feature`, соглашение — `specs/README.md`, скилл
`pozerkalam-gherkin`). Правило, по которому тренажёр судит игрока, записывается на языке
владельца и получает код требования. `@domain`-сценарий **исполняется**: `tools/gherkin-run.mjs`
поднимает страницу один раз, грузит словарь шагов (`tools/steps/domain.js`) и отдаёт каждый
сценарий одним вызовом `ghRun` — весь прогон ≈4 с, потому что на нём потом работает
мутационный гейт. Шаги работают с живой игрой: настоящий `loadLevel`, настоящий `setBody`,
ответы у тех же функций, что отвечают игроку. `@ui`-сценарий описывает то, что проверяет
инструмент в браузере, и связан с ним **кодом требования в имени проверки** —
`check('исключение в HUD не останавливает кадр (@app-crash-hud-survives)', …)`. `tools/gherkin-check.mjs`
сверяет связь в обе стороны: сценарий без проверки и код без сценария одинаково валят гейт.
Чек-лист ручной проверки (`docs/qa-checklist.md`) собирается из тех же сценариев
генератором и руками не правится — гейт сверяет его отпечаток. Два места, где гейт ломался:
код требования узнаётся по префиксу области, иначе в улов попадает `@font-face` из
css-строки инструмента; отпечаток чек-листа считается по **отсортированным** кодам, иначе
порядок обхода каталога объявляет свежесобранный файл устаревшим.

**Мутации** (`tools/mutate.mjs`, `tools/mutation.mjs`, зона — `tools/mutation-zone.json`,
скилл `pozerkalam-mutation`). Покрытие показывает, что строка выполнилась, а не что её
проверили: проверка может вызвать формулу и не сверить результат. Мутатор правит текст
инлайнового скрипта (Stryker сюда не поставить — мутировать надо `<script>` внутри `.html`)
внутри явного списка функций и констант; операторы — знак, действие, граница условия,
логическая связка, модуль, край и числовой литерал. Убивают мутантов `tools/units.js`
(≈60 утверждений с числами из `CAR` и из норматива, 0,6 с) и `@domain`-сценарии; оба набора
гоняются **в одной странице на мутанта**, иначе прогон не укладывается ни в какое время.
Мутант, ломающий загрузку страницы, считается убитым. Порог — храповик, вниз не опускается.
Правила, оплаченные на первой же функции: ключ мутанта — это функция, правка и отпечаток
**строки**, а не порядковый номер (номер съезжает от любой вставки выше по файлу, и список
эквивалентных наутро указывает на чужие места); база обязана быть зелёной до прогона, иначе
«убит» получает каждый мутант и сотня процентов означает, что не работает ничего; а
утверждение вида `corr === out − inn` — тавтология, она не падает никогда и не убивает
ничего (замена на числа подняла балл `sweep` с 33 % до 75 %).

## Architecture of index.html

Layout: CSS first (~190 lines), then HTML panels/overlays/touch controls, then one `"use strict"` script to the end. The script is organized in commented sections (`/* ---------- name ---------- */`) in dependency order; new code goes into the matching section.

**Coordinate system** (comment at ~line 264): all physics runs in the 2D ground plane `(u, v)`; the 3D world maps as `x = -u`, `z = v`, `y = up`. `yaw 0` points along `+v` ("north"), yaw grows turning right. Converters: `fuv`/`ruv` (2D orts) and `fwd`/`rgt` (3D).

**Software 3D renderer on Canvas 2D**: `setCam`/`toCam`/`toScreen` + near-plane clipping (`clipNear`, `NEAR` = 0.08 m — the headliner is 0.16 m above the eye, and the old 0.22 m plane cut it away when looking up, showing sky through the roof; a camera must never sit within 0.08 m in front of geometry it should not see, which is why the side-mirror cameras sit just behind their glass, with the housing ahead of them), `screenToGround` for the inverse (it reads the `viewCam` snapshot taken in `render`, because by the time a pointer event fires `cam` holds the last mirror's parameters), and a painter's-algorithm face list — geometry is emitted via `pushFace`/`pushBox`/`pushQuad`/`pushPoly` with lambert shading (`shadeCol`), then depth-sorted and drawn in `flushFaces`. The whole scene renders through `drawSceneInto`, which is reused for the main view and for mirrors (`renderMirror`) in cockpit mode. Painter's-sort rules paid for: (1) the sort key is the **distance from the camera to the centroid of the visible, near-clipped polygon**, not the depth along the view axis — depth changes with every degree of head rotation, so from the cockpit the panel order re-shuffled while looking around and the cabin flickered and «lost» panels; distance is rotation-invariant, and a face crossing the near plane is measured by its clipped part (the plain vertex mean of a wall beside the car went to ~0 and the wall was painted over the cabin); (2) inside the cabin the scene is two passes — world, flush, then own body + interior — because nothing outside can be nearer than the interior trim; mirrors and outside views stay single-pass so the own body sorts against neighbours; (3) a small detail sitting on a big face (exterior door handles and seams, door-card trim) carries a `bias` in metres that sorts it nearer — the host face's centroid is often nearer than the detail — and `pushFace/pushQuad/pushPoly/pushBox/pushBar` all take it; (4) interpenetrating boxes cannot be sorted at all (the seat back drew through the cushion, the visor through the roof header) — cabin parts sit on each other, never inside; (5) long world boxes are split into 3.5 m segments in `buildRenderList` (a 7 m kerb had its centroid nearer than the neighbour's wheel in front of it). `tools/sort-audit.js` → `sortAudit({yaws:[0,-90,135]})` in the page console counts wrong-order overlapping face pairs per pass (`[FIX:sort]`); it found all of the above — run it after touching geometry, the target is 0 in the interior pass. Three more per-frame rules in `flushFaces`/`pathCam`: **faces are not stroked** — `pathCam` pushes every screen vertex outward along the bisector of its edge normals by 0.9 **device** px (`EXPAND_DEV/pxScale` — 0.5 left a light seam on GPU Canvas at DPR 2, two half-covered edges; 0.9 is what the old 0.9 px stroke gave; `pxScale` is the DPR of whichever canvas is current, swapped for mirrors), damped for faces thinner than 1.5 px so edge-on loft slivers don't fatten into lines, orientation from the signed screen area — in screen coordinates (y down) a positive shoelace area is clockwise and `(dy, −dx)` points outward; with the sign inverted every face shrank and the world turned into a wireframe of gaps («всё в линиях»). This closes the anti-aliasing hairlines between neighbours (sky showed through them and shimmered) at zero extra raster passes — the old fill+stroke per face was half the frame time on a software Canvas; faces under 1 px² are skipped (far cars had hundreds). **Edges (рёбра) are the one exception to «no stroke», and only for box-shaped world objects** (walls, kerbs, hedges, cones, sign and light posts, mirror housings — `edgeOn` is set in a `try/finally` around `emitObstacles` and the housings; the car loft and the cabin never get them: «машины читались как сетка» was already paid for, and the cabin's structure comes from gradients and grain). A face carries an edge mask `em` (bit i = edge v_i→v_{i+1}) and `ecol` = the same colour × `EDGE_K` 0.55 through `shadeCol` (same hue, darker, fades in fog); `strokeEdges` draws one path per face over the contour `pathCam` just built (copied to `ESPX/ESPY` because the texture pass rebuilds paths), `EDGE_DEV` 1.5 device px, skipped under 3 px width. 1.1 px at 0.62 was invisible on the top edge of a wall (96 → 94). **Segment seams are masked**: `buildRenderList` cuts long boxes every 3.5 m and marks each piece `cut:{f,b,l,r}`; `pushBox` skips the end faces on a seam (hidden inside the neighbour anyway) and drops the vertical edges of the side faces there — otherwise every wall carried a dark line each 3.5 m. `tools/look-check.mjs` (`@render-edge-line`, `@render-seam-free`) measures both on level 2's wall by pixel profiles, and the seam check was proven red with the masks disabled before it counted as a gate. `cockpit-shots` guards it with `skyGap` (sky-coloured pixels in the dash band of the forward frame, live `getImageData`, limit 60, the mirror-glass rects excluded — a live side mirror reflects sky by right, and on the phone's wide frame it lands in the band with 1300 «gaps»; stroke gave 10, expansion 12 headless / 19 GPU, the inverted sign 36); and a cabin face may carry a second `fill()` of the same path after the colour fill — `grainFace` (material grain: a semi-transparent noise tile mapped through `ctx.transform` in the face's own metres→pixels frame, no `clip`, no `overlay` — both were dearer than the fill itself) and `imgFace` (a pre-rendered canvas as a `no-repeat` pattern mapped by three corners: speedometer, console screen, window switches, speaker grille), see **Cabin lighting**. A three-corner map is affine and puts the fourth corner at `s1+s3−s0`: when the real one is further than `IMG_PERSP_PX` (1 px), `imgFace` lays the picture by cells like `texFace` — every cell's corners projected honestly, `n ≈ √error` per axis, at most 8 — because on the 4.7 × 2.4 m pieces of the tram side the single map slid the picture 14–25 px off the face and the side «ехал» as the camera turned (#256); small faces (wheels, plates, dials) stay one fill. `world-check` `@render-img-perspective` puts a stripe on the tram side and checks its screen position against the projection of its own point from four oblique cameras; `FAULT=persp` restores the single map. What a face gets is decided by the pure `faceMode(f, s0..s3)`: mirrors are always flat; a gradient needs its two endpoints ≥ 1.5 px apart (a **degenerate `createLinearGradient` paints nothing** — edge-on faces vanished for a frame, «текстуры моргают») and a face ≥ `GRAD_MIN_PX` = 40 px, otherwise the mid colour `colMid`; grain fades continuously with screen area and tile minification (`f.gk`, thresholds would flicker); endpoints come from `toScreenClamped` (depth clamped to `NEAR`) so a face crossing the near plane never jumps between modes. `tools/cockpit-shots.mjs --sweep` turns the head −60…+60° by 1° on three pitches and counts mode toggles and degenerate gradients — the target is 0/0. `pushBar` cuts long bars into `seg` pieces with end caps only at the real ends — a cap on an inner joint showed through the neighbouring piece as a grey post.

**Car physics**: `CAR` const holds all vehicle dimensions/limits (kinematic bicycle model, Ackermann steering — `ackermann`, `sweep`). `stepCar` integrates at a fixed 1/120 s substep inside `frame`. Steering rate is speed-dependent (`steerRateNow`). The canonical pose is the rear axle (`car.ru/rv/th`); body center comes from `bodyPos()`/`setBody()` via `C2R`. Gear selector `P/R/N/D` lives in `car.sel`, drive direction in `car.gear`. `shiftSel` enforces a real automatic's rules: brake-shift interlock (leaving `P` requires `input.back`, i.e. S or Space held) and full stop before P/R/D — both refuse with a HUD warning (`selWarn`, `selBlockT`; touch also highlights the brake button via `body.needbrake`). Space is a second brake key, not a handbrake. `selectGear(target)` walks the lever to a position and reverts to the starting one if it can't get there, so a single command never strands the car in `N`. Four ways to shift, all through those same rules: `Enter` (D ⇄ R — the constant move while parking), `P`, `,`/`.` one position at a time, and clicking the P R N D letters in the HUD (`#gearVal span[data-gear]`) or the touch `#tgear` buttons.

**Self-centering** (the wheel returning on its own) uses the real law — self-aligning torque grows with the *square* of speed: `back = min(casterMax, casterGain*(v² − casterV²))`, gain `rad(2.2)` per (m/s)², cap `rad(50)`. Keeping the `casterV` threshold at 2.2 m/s is what makes the feature safe: below ~8 km/h there is no return at all, so parking maneuvers, the level hints that say "hold full lock", and the calibration of all 11 demos are untouched, while at 15–19 km/h the wheel unwinds in 0.7 s. Measured: 9 km/h → 11 s to unwind, 11 km/h → 3.7 s, 14 km/h → 1.4 s, 19 km/h → 0.7 s. **A linear-in-speed law cannot be used** — it already unwinds the wheel at parking pace and breaks parallel parking. `demoStep` holds the wheel only while `|err| > 1.5°` and *brakes in that same condition*, so a caster that drifts the wheel inside the dead band would make demos stutter between "correcting" and "driving": the narrow 0.35° trim band exists for that, and it is gated on `|vel| > casterV` — widening it below the threshold changes the arc radius and rips up the segment calibration (it cost L11 a failed run before being gated).

Full lock is 34.5° at the wheels = **1.49 turns** of the steering wheel (`steerRatio` 15.5); `atLock()` marks the stop, which colours the rim mark red and clicks `tone()` **on the edge** (`lockWas`), never per frame. Because lock is past one full turn, the 12-o'clock mark alone cannot tell 0.2 turns from 1.2, so `steerTurnCol()` colours it by the turn count — first turn yellow, second orange, lock red — for both the HUD steering panel and the cockpit wheel, and `drawSteerPanel` draws the rotation from the fixed tick as a yellow ring for the first turn plus a separate outer orange ring for the second (customer fix #152).

**Collision & clearances**: two-phase. The OBB SAT with minimum translation vector (`satMTV`) is only the **broad phase**; the contact itself is decided on the car's real ground footprint — `CAR_HULL`, the convex hull of the own body model's footprint (`hull` of the sedan in `car-mesh.json`; the loft's stations, `CAR_HULL_LOFT`, only when the model is missing) — against the obstacle's shape (`polyMTV`, generic convex SAT; a neighbouring car is the hull of its own body, `carHullOf`, everything else a rectangle). The OBB is 4.42 × 1.80 while the body tapers at both ends (the sedan's nose at z=2.21 is 0.87 m wide, its tail 1.19 m; the loft's were 1.48 and 1.56 when these numbers were measured), so the rectangle's corners hung outside the metal and a touch was counted **2–9 cm before the bodywork met anything** — 1.7 cm at 6° of yaw, 5.5 cm at 20°, 9.2 cm at 35°, and 13.5 cm car-to-car at 45°. That is what «габариты кривые спереди и сзади, по текстурам ещё не задел, а пишет соприкосновение» meant. The narrow phase runs **only** on obstacles the broad phase already flagged, so the per-frame cost is a rounding error (+0.1 ms on the exam scene). `drawRefs` and `emitCornerPosts` draw that same hull — the frame and the posts may never drift from what a hit is measured against — and the posts sit on the hull vertex furthest in each diagonal (sedan: front (±0.87, 1.94), rear (±0.86, −1.92)), not on a rectangle corner floating beside the bumper. Front and rear edges of the frame are the hull edges turned more than 30° across the car (`REF_CHAINS`), not everything beyond a z threshold — the model's vertices are sparse, and by the old `z ≥ 1.40` the edge along the fender from z 0.99 to 1.94 was painted as the yellow front edge for a whole metre. **`clearances()` deliberately stays on the OBB**: every demo threshold is calibrated against its readings, and a conservative sensor is the safe side. `tools/hull-check.mjs` guards all of it — it binary-searches the first position the *game itself* calls a touch (through `resolveCollisions` and the `_touch` latch, not through helper functions) over 15 headings against a wall and 8 against a parked car of each of the three bodies, fails above 1 cm, and also drives into a wall at three speeds to prove the smaller shape did not open a way through. A hit is counted on the *start* of contact, latched per obstacle in `o._touch` (reset in `loadLevel`/`restart`) — counting while overlapping gave a stationary car on a kerb 18 hits in 10 s. Soft-obstacle drag is `exp(-2.5*dt)`, not a per-substep constant. HUD clearances (front/rear/left/right, blind zones) come from ray casts `rayOBB`/`castMin` in `clearances()`, capped at `SENS_MAX` (3 m): five rays per side **including the body corners**, plus one diagonal per corner folded into both adjacent readings. Perpendicular-only rays were blind to obstacles sitting diagonally off a corner and overstated the gap by up to ~0.9 m; the remainder (~0.23 m worst case) is the honest blind spot a real parking sensor has. **Demo segment thresholds (`frontLt`/`rearLt`/`leftLt`/`rightLt`) are calibrated against these readings** — changing the sensor model silently breaks every demo that uses them, since a condition already true at segment entry ends that segment instantly and the whole chain cascades. `clearances()` also returns `corner` — the single body corner with the least room (three rays each, below `CORNER_WARN` = 1.2 m), computed here rather than at draw time because `emitCornerPosts` also runs in the mirror passes. It carries `CORNER_KEEP` hysteresis (0.08 m): alongside a wall every corner on that flank reads the same gap, and without a bias toward the already-lit corner the highlight flips between them every frame.

**Showing where the car ends** (the player's own complaint: "не видно габаритов"). `opt.refs` is a three-position level, not a toggle — key `B` cycles it, `REFS_NAMES` names it, `trainer_refs` persists it: `0` as in real life, `1` the ground frame plus corner posts, `2` adds the distance marks and blind-zone lines (`#blindCell` follows level 2). Mobile defaults to 1. **`emitCornerPosts()` must not be gated on `camMode`** — it was cockpit-only, which is exactly why the chase camera the player actually uses showed no extremities at all. The ground frame in `drawRefs()` is drawn on the same footprint the collision uses (`CAR_HULL`, see **Collision & clearances**), so it cannot drift from what a hit is measured against; front edge yellow, rear orange, and the nearest corner turns red with a distance pill from `drawMarkLabels` (which claims its `labelBoxes` slot first, ahead of the phase markers). The hood-corner whiskers in `emitCarMesh` brighten only for the player's car — `lights` is what separates it from the parked ones.

**Levels**: `LEVELS` array, 32 built-in entries plus the player's own pads appended at load (1–13 манёвры двора, 14–19 дриллы габаритов, 20–22 экзаменационные упражнения: эстакада/задний ход/остановка у тротуара, 23–26 город на собственной геометрии: повороты/разворот/пешеходный/уступи, 27–31 город на общей карте: светофор/перестроение/разворот с трамвайных путей/кольцо/косой перекрёсток, 32 экзамен-маршрут). Each level is `{ name, task, tip, steps[], refs, hacks[], transfer, build(), marks()?, phases[]?, coach(state)?, examRoute()? }`:
- `build()` returns `{ obs, dec, start, goal, ramps?, city? }` — obstacles from factories `wall/kerb/hedge/pcar/cone/post/sign/actorCar`, road decals from `stripe/circleDec/roadDec/crossDec/zebraDec/stoplineDec`, plus `start` pose and a `goal` rectangle with angle tolerance (`goalPoseOk` + stopped = `goalReached`, held ~0.55 s). **`goalPoseOk` requires ALL FOUR body corners inside the rect** — city-level goal zones are w=3.0/l=5.6 because demo «морковки»-погоня leaves 0.2–0.4 м of lateral offset; a 2.6-wide zone silently never triggers.
- `phases[]` (replaces `coach` on converted levels) — stateless if-chain: `phaseTick(dt)` each frame picks the first entry whose `when(s)` is true; a phase carries `hint` (full-sentence fallback text), `marks` (names resolved from `marks()` into `p._marks` at `loadLevel`), and optional `mirror` ('left'/'right'/'center' — glows in cockpit view). `s` is `curS`: pose, `gear`, `vel`, `steer` plus the four live clearances (`front/rear/left/right`). `coach(s)` remains the fallback for levels without phases (level 9 only).
  - **Structured card fields** (all 12 phase levels carry them): `icon` (direction glyph ⬆/⬇/⏹/🅿), `act` (short action ≤ ~45 chars — what the card shows), `goal` (`{metric:'ang'|'front'|'rear'|'left'|'right', target, dir:'up'|'down'}` for the live progress chip, or `{text}` for landmark goals), `wheel` (`lockL/lockR/left/right/straight` → mini steering pictogram), `move` (`fwd/rev/stop` → target-gear badge), `why` (long explanation, rendered by the disclosure block). `hint` stays as the fallback: the card renders it when `act` is absent, custom pads and «Полигон» work unchanged. `phaseTick` passes the whole object through, so extra fields are safe. **Chip targets come from the demo segment that leg mirrors** (`dist/frontLt/rearLt/…`), never from a marker of a different leg — L1's «до жёлтой линии» text contradicted the demo's `dist:0.5` and drove the tail into the kerb; the number lives in the chip, not in the prose.
  - A phase switch needs the candidate to hold for `PHASE_HOLD` (0.22 s). Without it the hint flickers, because stepping the selector P→D passes through R and `car.gear` goes negative for a frame.
  - **Chains must cover every reachable state and stay monotone along the maneuver.** Traps hit in practice: a coverage gap makes a later unrelated phase win (guard forward phases with `gear>=0`, end with an unconditional entry); keying purely on heading makes the chain run *backwards* at the end of the maneuver, when the angle sweeps back through the same band; and a reverse phase with no positional bound fires when the player backs up far from the pocket. Discriminate the legs by a value that only moves forward — lateral position `u` in the parallel levels — bound them to the stretch where the maneuver happens, and normalize to 0…360 (`(deg(angNorm(th))+360)%360`) wherever the heading crosses ±180°, as in levels 2 and 3.
  - **Phase thresholds must equal the drawn marker positions.** A hint that says "stop here" 0.6–1 m before the line the player can see teaches the wrong reference point; when a phase mirrors a demo step, take its boundary from that segment's target (level 3's приёмы switch at 148°/212°/258° because the demo drives to 145°/205°/262°).
  - The `P`/`N` selector notices never replace the phase hint — they prefix it ("⏸ P · … Дальше: …"). Without that the very first instruction of a level was a lecture on the gear selector and nothing about what to do, so a new player just sat still.
  - **Every hint is a pair: action + the sign it is finished** ("веди, пока «угол к цели» не дойдёт до 45°", "назад до 0,3 м по «зазоры сзади»", "до голубой стоп-линии"). A hint that only names the action leaves the player overshooting the point they were aiming for. The termination sign must reference something visible on screen — that is why the HUD carries an **«угол к цели»** readout (heading minus goal axis, coloured by the level's tolerance): hints referenced a 45° angle that the panel never showed.
  - Three teaching layers sit *above* the phase hint in `updateHUD`'s priority chain, because each answers a question the phase hint can't: `selWarn` (why the shift was refused), `game.hitMsg` from `hitReason()` (which corner hit what; the geometry lesson now lives in `game.hitWhy` and renders as the card's disclosure block), and `goalMiss()` (why standing in the zone isn't a pass). Two guards keep that layer honest: `goalMiss` is only *shown* when the car is nearly stopped or the pose is already correct — on the move mid-maneuver «стоишь под 50°, доверни» fired exactly when 45° was the goal; and its advice must name the movement direction and the protruding side («сзади лишь 0,1 м — подай вперёд, забирая левее» — computed from body corners in the goal frame), because an addressless «вкатись глубже» drove a literal-minded learner straight into the neighbour. The angle case gets the phase's `act` appended as «Дальше: …»; the self-contained cases must not — the phase next to them may say the opposite («остановись») and the pair reads as a contradiction.
  - **The coach card** (`coachCard(kind, icon, main, goal, ph)` in the HUD section): every branch of the priority chain maps to a kind — `k-stop` (refused shift, red), `k-hit` (collision, orange), `k-info` (toast), `k-almost` (goalMiss, yellow), `k-gear` (P/N, blue), `k-act` (phase), `k-ok`, `k-demo` — coloured left edge + icon, so message types are tellable apart at a glance. The card's `innerHTML` is rebuilt only when a composite key changes (`coachKey`); dynamic strings go through `textContent` (pad names are user input). **Text contract: the card's `textContent` must read as a plain sentence** (spaces between blocks) — the scripted learner and screen readers consume it. The goal chip shows «→ цель X · сейчас Y» + a progress bar from the value at phase entry (`coachGoalTick`, per-frame writes only on change); tapping the chip pulses the corresponding `#bar` cell (`cellPulse`) — this is what ties the hint's words to the HUD numbers. `goalMiss()` is called once per frame and cached — it used to be evaluated twice in the old ternary chain.
  - **Progressive disclosure**: a phase's `why` renders as a collapsible block. Auto-expanded for the first 3 launches (`trainer_runs`, incremented once per session in `doAct('start')`), then behind the «?» button / `Slash`. The toggle is an XOR against the auto-default — a plain OR made the block impossible to collapse for a novice. On `compact` the «?» is hidden; tapping the card toggles it with a 4 s auto-collapse (`#coach` gets `pointer-events:auto` only via `.haswhy` there). Key names in hints say `Enter`, never «.» — on ЙЦУКЕН the physical Period key types «ю» and the literal advice didn't work; `Slash` was free for disclosure for the same reason.
  - **Onboarding tour** (`showOnboard`, gated by `trainer_seen`): 5 sequential callouts over the `#thelp` layer (card → «угол к цели» → зазоры → селектор → демо/⟲), pulsing ring on the live element rect, game paused. Desktop runs it from `doAct('start')`; mobile chains it after the touch-buttons tutorial in `closeTouchHelp`. The backdrop handler routes by `onbActive` — closing the tour must set `trainer_seen`, not `trainer_hint`.
  - **First-drive guide** (`tut`/`TUT`/`tutTick`, gated by `trainer_drive`): four LIVE steps on the coach card — hold brake → Enter (D) → release, feel the creep → throttle to 5 km/h — each `done()` watches real input/car state, advancing only on the actual action; a static «how the automatic works» paragraph demonstrably didn't get novices moving. Runs after the tour (`closeOnboard` → `maybeStartTut`), owns the card slot between `hitMsg` and `goalMiss` (selWarn still outranks it — a refused shift IS the lesson), starts only from an untouched `P` (`!game.moved`), and `restart()` resets `tut.i` because the car returns to `P`.
- `marks()` returns named world-space teaching markers built once per load: `mline` (ground line + label), `mpoint` (pillar beacon), `mspot` (ground circle), `marrow`, `mghost` (ideal-pose car outline, turns green via `ghostOk`), `mcarpin` (pin on own car corner). Rendered by `drawMarks` (geometry before `flushFaces`) + `drawMarkLabels` (screen-space pills, main view only, ≤3 labels, ≤2 on MOB; overlapping pills are pushed upward via `labelBoxes`). Toggle `opt.marks` (key `O`, localStorage `trainer_marks`, default on incl. mobile).

The win screen (`winHTML`) carries only the results, the comment and three moves from `winActsHTML` — «Выбрать уровень», «Заново», «Следующий уровень» with the next level's name under it; the full level list used to sit there and buried the results (customer fix #149). **One restart, one word — «Заново»** (side button, win and fail screens, ≡ menu «Уровень заново»): four different labels for the same action read as four actions. On `compact` the three moves stay in one row — stacked full-width, the main button fell below the fold.

Segment fields: `g` gear, `s` steer (-1..1), `aim` point steering (`demoAim`, works in reverse), `blink:'L'|'R'|null` (applied at segment entry — city demos must themselves show the ритуал or the detectors would fine them), end conditions (`th/dist/uGte/uLte/vGte/vLte/frontLt/rearLt/leftLt/rightLt/goal/time`), speed caps `slow` (~5 km/h) / `vmax`, `green` (hold until the level's traffic light is green with ≥4 s left — a fixed `time:` pause drifts against the 24 s cycle and the level-27 demo drove itself through a red), and `say` — narration text shown in `#coach`; before a `say` segment the car brakes for `sayT` (~1.9 s) so it can be read, and active marks pulse. Demo geometry is exact: stop points and arc angles are derived from full-lock rear-axle radius R≈3.84 м (lateral shift of a two-arc parallel park = 2R(1−cosφ)); don't tune them by eye, recompute. Three calibration lessons paid for in this file: погоня-`aim` at a far point NEVER converges laterally — use a chain of near «морковок»; a left U-turn's heading goes NEGATIVE (target `th:rad(-176)`, not +178 — `angNorm` puts the miss at 356°); a sensor-based end condition true at segment ENTRY (e.g. `rightLt` while passing a parked row) ends the segment instantly and каскадом рушит цепочку — prefer geometric ends (`uGte/vGte/th`).

- **Ideal trajectory**: `computeIdealPath()` re-runs the level's demo headlessly at `loadLevel` (state saved/restored, `say`/hits/sound suppressed, `game.t` restarted from 0 and advanced per step — the traffic-light phase is a function of it, and with time frozen a «wait for green» segment never ends, ~5 ms) and samples the body path every 0.35 м; `buildIdealDraw` splits it into forward/reverse polylines with direction chevrons (`level.idealDraw`), drawn by `drawIdealPath` under the markers (green = forward, orange = reverse). No per-frame allocation. Gated on `opt.guides`, not `opt.marks` — trajectory lines (prediction arcs, wheel trails, ideal path) all default OFF and toggle via `G`/`T`: on a first launch they buried the teaching markers in clutter; the markers (`opt.marks`) stay on.

Floating controls: `#restartBtn` + `#demoBtn` + `#fbBtn` + `#trafBtn` on desktop (real `<button class="sidebtn">`, hidden in compact/hud-off/overlay — as `div`s they were pointer-only and the traffic density had no keyboard path at all; a mouse click blurs them, otherwise the next `Enter` (D ⇄ R) pressed the focused button again) and `#trestart` on touch. Touch mode (`MOB`) is auto-detected and persisted; three HUD modes cycle via `cycleHud`. `localStorage` keys: `trainer_hint` (touch tutorial seen), `trainer_seen` (HUD onboarding tour seen), `trainer_drive` (first-drive guide passed), `trainer_runs` (launch counter — auto-expands the card's «why» for the first 3), `trainer_hud`, `trainer_touch`, `trainer_marks`, `trainer_refs`, `trainer_mirrors`, `trainer_levels` (custom pads), `trainer_progress`, `trainer_traffic` (плотность потока); аккаунт — `pz_auth` (refresh и карточка), `pz_nudge` (предложение войти после первой победы показано), `pz_debug` (`an` — события аналитики в консоль). Ключи аккаунта нарочно `pz_*`: адаптер ЯИ зеркалит каждый `trainer_*` в облако площадки. The CSS ends with three blocks that must stay last: `@media (max-width:600px)` (the 568 px band), `@media (hover:hover)` (every hover rule lives there — on touch a hover stuck after the tap) and `@media (prefers-reduced-motion:reduce)` (onboarding ring and cell pulse go static; turn signals keep blinking — they are the signal and carry colour). The selector letters `#bar .lever span` sit at `opacity:.5`: at `.22` white on the panel measured 1.95:1 and they are click targets. Setting buttons in the ≡ menu name the transition («Поток: обычный → плотный», «Скрыть все панели»), never the state — «Коробка: автомат» was read as a status line and the owner never found the switch. Numbers shown to the player use the decimal comma («1,93 м», «5,1 с»); `learner.js` reads only integer degrees. Polish rules on top (26.09): every `button` has `:active{transform:scale(.96)}` and `touch-action:manipulation` (touch feedback on press, not on release; the 300 ms tap delay off), the hover block is `(hover:hover) and (pointer:fine)`, overlay card text is selectable (`#overlay .card{user-select:text}` plus the `selectstart` guard lets it through — steps and results get copied; the game layer and buttons stay unselectable), `✉︎` carries U+FE0E so iOS draws a glyph instead of a colour emoji, the viewport meta has `interactive-widget=resizes-content` (the feedback form under an Android keyboard), and `maximum-scale=1`/`user-scalable=no` stay on purpose: a pinch is a game gesture (camera zoom), the inputs are 16 px on compact so focus no longer zooms. `#coach` is `role="status"` with the live chip value `aria-live="off"`. `toast(msg, secs)` writes a short settings notice into the coach line (`note`/`noteT`), ranked below `selWarn` so it never buries a refused shift.

**The frame survives an exception.** `frame()` runs its three blocks under separate `try` — simulation, `render`, `updateHUD` — and `requestAnimationFrame` is requested first, so a throw in the HUD leaves the world moving, a throw in physics leaves the card alive, and the loop never dies (level 18 once threw a TypeError 120 times a second and the card kept the previous level's text). `crashHit(where, e)` logs `console.error('[crash]', …)` **once per place** (`crashN`; per-frame logging would bury the console and cost fps), toasts «перезапусти уровень (R)» — and when the HUD itself is what fell, writes that text straight into `#coach`, because the toast is rendered by the HUD it cannot reach — and sends `crashReport`: **one** POST per session (`crashSent`) to the same `/api/feedback` as a manual report, `kind:'bug'`, text `[crash] <where>: <message>` plus six lines of stack, the usual `fbCtx()` (build, level, fps). `window` `error`/`unhandledrejection` go through the same `crashReport`. It is silent under `navigator.webdriver` and on `file://` — every headless gate drives the real `frame`, and without that guard each tool run would page the owner in Telegram; `window.CRASH_REPORT_FORCE` is the test-only bypass. `progAll()` also drops non-object entries and coerces `n/clean` — a garbage `trainer_progress` used to throw inside `win()`; and `doAct()` ignores an empty action. `tools/crash-check.mjs` (`@app-*`) breaks the game from inside and checks all of it.

**Keyboard vs. text input.** The `keydown` listener is global, so `typingInField(e)` must skip it whenever focus is in an input — key codes are physical, so a Cyrillic "к" arrives as `KeyR` and used to restart the level while the player was typing a pad name. Modal states filter commands too: `pressKey` passes only `K`/`Delete`/`Backspace` while the editor is open (a digit key used to swap the level out from under it), and `doAct('resume')` re-shows the win screen instead of closing it, because `game.done` freezes physics and a closed overlay left no way out.

**A demo must not touch anything, and its carrots decide whether it does.** `demoAim` is pure pursuit, so the car always cuts inside the line joining the carrots — the roundabout chain handed a segment over 45–70° of arc before the next carrot and the path fell to radius 8.07 against island kerbs whose edge is at 8.25, riding them for half the run. Carrots on one radius every 30°, each segment ending ~3 m short of its own carrot on whichever coordinate is monotone there (u along the bottom of the ring, v up the right side), hold the path at 9.74. Two more rules paid for on the same demo: a carrot placed exactly on the target lane centre is not enough on the exit — the car arrives at it still angled and lays its outer flank on the kerb, so the first exit carrot goes a metre PAST the lane centre; and a turn signal set more than ~60° of heading before the maneuver self-cancels on the way (`stepCar` watches heading, not the wheel), so on a ring the blinker segment must be the one right before the exit. The parallel park had the same class of defect one metre wide: stopping 20 cm too far forward before the maneuver put the nose into the neighbour's rear corner during the second arc. `tools/level-audit.mjs` fails the run on any contact — it latches `o._touch`, because `satMTV` after the frame sees nothing (a solid obstacle is already pushed out).

**A demo must survive its own level's detectors.** The headless regression only proves the maneuver is drivable — it never runs `violationsTick`, so a показ can commit the very violation the level exists to teach and every player following the green ideal line collects the same penalty. `tools/demo-vio.mjs <индексы>` replays each demo in real time with the detectors dosed in parallel (a clean level prints an empty code list) and `tools/yield-sweep.mjs <индекс>` walks the level's own ideal path against the actor with a growing start delay, printing the minimum separation and the codes for each — that sweep is how `YIELD_TCA/GAP/LAT` were set. Replaying each city demo that way found four: level 23's demo drove the whole middle street on the ONCOMING half (`aim` at v=+1.65 instead of −1.65, a hard strike on an образцовый проезд), level 25 paused for narration with its tail on the zebra, level 27 ran a red, level 31 was fined by the yield detector for a legal pass. Re-run that probe after touching a city demo, a detector zone or a detector threshold.

**Testing the teaching, not just the code.** The demo regression proves the maneuvers are physically solvable, but a demo replays hardcoded segments and never reads a word of the UI — it passed every level while a real player would have sat still in `P`. The check that finds those defects is a scripted "learner": an agent that reads `#coach` each frame and does only what the text says. Run it after changing hints. `tools/level-audit.mjs` covers the same ground without the learner's own driving errors: it replays every level's demo headlessly and calls `phaseTick` per frame, producing the exact tape of «which card was up, for how long, and how far its chip's bar got». That is what found a level with no live hint at all (the six габарит-drills showed the `genericCoach` fallback «Свободная площадка» while driving), a phase chain that plays backwards after the maneuver is over (level 29 told the player to signal and start the U-turn again while parked in the goal zone), a chip whose bar never moves, and `updateHUD` throwing every frame. Its chip criterion is the **player-visible** one — `pct >= 100` exactly as `coachGoalTick` computes it — because a `target:0` angle chip never satisfies a strict `v <= 0` and a stricter tool cries wolf on every phase. Exit 1 on: a page exception, a level whose card is empty, a level with neither `phases` nor `coach`.

**Feel-the-extremities drills** (`precision` on a level, `drill:true` for the level-picker section): the goal is a *gap*, not a rectangle. `goalReached` branches on `precDef()`; `precGap()` reads the trained side's clearance, or the level's own `measure()` when the target is something the sensors cannot see (a painted line is not an obstacle). **The trained side's HUD number is replaced by `?` until the car stops** — this is the mechanism, not decoration: with the real number on screen the player aims at a digit instead of learning the distance. Stopping *is* the answer (`precTick`, 0.6 s hold, gated on `game.moved` so the initial standstill in `P` doesn't count), and the attempt reveals once — `precShown` stays set until `restart()`, otherwise creeping forward a centimetre at a time buys unlimited free feedback. `precision.th`/`thTol` guard the sides, where a car parked askew shows the same 20 cm on its nearest corner without actually being parallel. **`side` is optional and every consumer must treat it so**: the level whose target is a painted line has only `measure()`, and the `?`-masking line in `updateHUD` read `$({front:'cf',…}[p.side])` unguarded — `$(undefined)` is null, and level 18 threw a TypeError 120 times a second. Everything below that line in `updateHUD` (the coach card, «угол к цели», blind zones, the gear and blinker badges, `frameCost`/`perfTick`/`qTick`) simply stopped running on that level, and the card kept the previous level's text; `render` sits above it, so the world still drew and the level looked alive. Each drill also carries a one-entry `phases` chain: the reveal itself is already handled by `goalMiss()` → `precReport()`, which outranks the phase hint, so one unconditional card carrying the instruction is the whole chain. Tuning check that matters: a scripted run of random stopping positions passes ~1 % of the time — a drill that random stops can pass teaches nothing.

**Progress** (`progAdd`/`progOf`/`progLine`, keyed by level name): runs, clean runs and best time per level, written in `win()`. Drills instead record `bestErr` in centimetres plus `bestBlind` — the same error achieved with `opt.refs===0` — because on a precision drill time is the wrong measure and rewarding it pushes the player to hurry and miss. Shown on the level-select cards and the win screen. It exists because a trainer needs a repetition loop — without a visible record there is no reason to drive the same level twice, and repetition is where the skill actually forms.

**HUD layout**: `#topright` carries the hit counter and the level index only — there is no running timer during a lesson (customer fix #150); the time is shown once, in the lesson results (`winHTML`), and still feeds `progAdd`. The key hint `#hint` is a left column, one command per row, most important first (`HINT_AT`/`HINT_MT` + `HINT_ALL`, built by `syncHintLine`): as one « · »-joined line it ran across the whole screen over the minimap (customer fix #151). `layoutHint` fits it into the band between the bottom of `#topleft` or the left mirror and the top of the steering panel (`drawSteerPanel` at `H−186`): rows that do not fit are hidden, the last row «H — справка и все клавиши» always stays, fewer than two rows hide the block — so it can never cover the mirror, the card or the panel (10 rows at 1440×900 with mirrors, 5 at 1280×720). It re-measures every 15 frames, not per frame — reading the card's rect forces a layout. `#coach` lives in the band between `#topleft` and `#topright` (fixed `left`/`right` + `margin:0 auto`) so it can't cover them. The in-cabin mirror is drawn on the canvas, so `render` publishes its bottom edge as the `--mirbot` CSS variable and compact-mode `#bar` positions itself below it. The `.sidebtn` buttons stay in the 102–167 px band, above the side mirrors (whose top is `clamp(H*0.40, …)` — they never start higher while the buttons are visible), or an HTML button silently swallows taps aimed at a canvas mirror. `updateHUD` runs every frame, so all its DOM writes go through `setText`/a cached `car.sel` — writing `innerHTML` or `textContent` unconditionally costs a style recalc per frame. While an overlay is open, arrow keys and Space are left to the browser so a long task list can be scrolled; `Escape`/`H` close the task and start overlays but deliberately not the win screen, which is the only way out of `game.done`. The touch tutorial (`#thelp`) pauses the game while it is up, so the level timer doesn't run while it is being read. **The touch bottom band is width-budgeted, and the budget must be recomputed whenever anything in it changes.** It holds 14 targets across the screen: steering (3), `#tmenubtn`, `#tgear` (4 gears + 2 turn-signal arrows), `#trestart`, drive (3). `#tmenubtn`/`#trestart` are offset from the centre by **half of the whole `#tgear` row**, not half of the gear letters — the old ±101 was computed for four 44 px letters while the row has six tiles (6·44 + 5·5 = 289, half 144.5), so ≡ and ⟲ lay exactly on the arrows and the turn signals could not be pressed at all on a phone, silently failing the blinker ritual that the city/exam detectors score. At 667 px (SE landscape) the band does not fit at stock sizes, so a **width** media query (`max-width:760px`) shrinks every element — the compact block above it keys on `max-height:420px` and never catches that screen. `touch-check` asserts zero overlap over 40 px² and no target under 36 px on five phone sizes. **At 568 px (iPhone SE 1/5s) the band cannot hold ≡ and ⟲ at all** — between the steering cluster and the gear row there are 34 px for a 38 px button, and ⟲ sat entirely on ТОРМОЗ, so every brake press restarted the level; below `max-width:600px` both buttons move to the top-right corner (y 46–84, under the hit counter, above the right mirror). Glyphs: the arrows are `◀ ▶` (U+25C0/25B6), never `⯇ ⯈` (U+2BC7/2BC8) — the system font stack has no coverage for the latter and draws them as a stack of bars; nobody noticed for months because the buttons were covered.

**Cameras**: chase / top-down / cockpit (`opt.camMode`, cycled with C, V jumps to cockpit). Mirrors render in every mode (`opt.mirrors`, key Z); in cockpit the camera sits at the driver's eye and `camInsideCabin()` adds the modelled interior. Mouse/pointer drag orbits, wheel zooms.

**Sky**: `drawSky` draws the `sky-pano` panorama (series 2): one period is 180° of heading (over 360° the clouds stretched fourfold), the vertical is squashed by `SKY_PANO_SY` 0.35 (at one scale the distant city stood up as 170 px skyscrapers, a neighbouring block rather than haze), the bottom of the image sits on the **projected horizon** of the current camera (mirrors included), above it the image's top colour; the copies join without a seam because `clean.py` cross-fades the right 6 % of the source into its left edge. At quality `SKY_PANO_Q` (5) and up, or without the image, the old gradient — one more full-screen `drawImage` is not free on a software canvas. `@render-sky-pano` checks the horizon to 2 px and the seam.

**Shadows**: every obstacle casts one, not just cars. The offset comes from `LIGHT` itself — `SHADOW_K = LIGHT.x/LIGHT.y` (0.419 per metre of height), applied as `(du, dv) = (+K·h, −K·h)`; the polygon is the convex hull (`hull2`) of the footprint and its offset copy. Obstacles never move, so `shadowPoly` runs once per obstacle in `loadLevel`/`edRebuild` into `o._shadow` and the frame only fills it; the player's `carShadow` is the one computed live. Before this the car's shadow was a hand-tuned 0.34 m offset tied to neither the body height nor the light direction — it fell where nothing was lit from.

**Sightline rule, upward**: nothing in the cabin may hang into the windshield opening from above — the stowed sun visors lie on the headliner BEHIND the roof header (`z ≤ 0.22`, header from 0.23; lower front edge at +19.9° from `EYE`). They used to sit at z 0.32–0.52, y 1.31–1.35, i.e. in front of the glass top edge, and covered the 7–16° band — exactly where the lens of the traffic light you are approaching sits (#110). The glass opening and the interior-mirror housing are constants, `WSHIELD` and `CMIR`, read by both `emitDash` and `tools/light-check.mjs`: a lens the tool finds unlit from the cockpit is classified by the eye→lens ray — outside `WSHIELD` (roof, pillar; to the right of the axis the header is at ~15°, not the straight-ahead 17.5°) or through `CMIR` is honest, through the glass and unlit is a defect. **Sightline rule, downward**: everything in the cabin that is not a window must stay **below the hood line** as seen from `EYE` — the hood edge (`HOOD_Z/HOOD_Y`) is at −8.9°, so the wheel rim top (centre 0.90, rim top 1.085 → −12.7°) and the binnacle hood (1.06 → −12°) sit under it, and the roof header (1.39, bottom 1.36 → +17.5°) above the windshield. With the wheel centred at 1.01 the rim covered the road 7–30 m ahead and the owner «did not see where to drive». Check with a cockpit screenshot after moving anything on the dash.

**Driver's eye**: `EYE = {lat:-0.36, y:1.22, z:-0.20}` (body frame) feeds both `fpEye` and `blindZone`, so the cockpit camera and the «не видно перед / за» numbers can never disagree; with the eye at `z=0, y=1.27` the roof header was 0.26 m ahead and the A-pillar 0.39 m away and both rendered as slabs across the view. The windshield gets a faint tint quad plus a dark sun strip (alpha colours: a 4th component in `col` makes `shadeCol` emit `rgba`), sorted with a negative `bias` so the wheel and dash draw over it.

**Car body — near cars are a model** (`emitCarModel`, `<template id="car-mesh">`, 162–279 faces per body): the own car always, others within `CAR_MODEL_D` 45 m (at 20 m only 2 of 7 cars on level 1 were models and the owner never saw the new ones — «все равно старый вид»); the loft below draws from 45 m to `TRAF_LOD`, `emitCarLow` beyond. **Car body — ready models, not home-made ones** (plan `.ai-factory/plans/car-bodies-rgsdev-models.md`, board #252). Two home-made attempts were rejected by the owner: sections lofted from the cabin and then from his own blueprints read as boxes («не реально»), and his blueprint pictures projected onto those ~300 faces read as «мятая бумага» — the blueprint's own shading landed on faces at other angles and a lamp got split between two projections. A painter's renderer with flat faces cannot carry a realistic car, so the bodies are a coherent low-poly set made for flat faces: **Free Low Poly Vehicles Pack** (Raphael Gonçalves «Rgsdev», CC0) — `Sedan` → `sedan` (the own car and style B), `Hatchback` → `hatch`, `SUV` → `cross`. `tools/blender/models.py` (run in Blender, FBX import) maps them onto the game **as a whole — one scale factor per axis**: across the body without mirrors is 1.80, along the length without the plate is 4.42, up the model wheel is the game wheel (0.33). Up comes out within 2 % of across, so the cross-section keeps the reference proportions; only the length is stretched (sedan 8 %, hatch 11 %, crossover 12 %) to the one car size every demo and drill is calibrated on. The first fit bent the models locally so that their footprint landed on the old loft hull — a scale per z slice, two height bands, a piecewise map along z, cuts at the hull corners — and the owner saw the cars «плывут»: the nose stretched 2.4 times and the lamps smeared over it (rejected 03.10.2026). **Now the rule is the other way round: the touch footprint comes from the model** (`hull`), while the broad phase and the sensors stay on the 4.42 × 1.80 rectangle the model is inscribed in, so `clearances()` and every demo threshold are untouched; `level-audit` after the switch printed exactly what it printed before and found no contact, and the touch scenarios moved by measurement (level 14 at 35°: the hull touches the wall 24 cm after the rectangle). Wheels dropped (the game's turn and wear style discs, drawn on `axles`); mirrors dropped — **every face with any vertex beyond 1.16**, judged by the face centre the mirror base stayed. The plate stuck out 2 cm in front of the bumper and would be the car's frontmost point: it is seated on the bumper, its two halves merged into one face with the plate image. The exhaust pipes are loose 37 cm parts stuck 4 cm out of the bumper — interpenetrating geometry the painter's sort cannot resolve (painter's rule 4): one pipe was drawn whole over the bumper, the other whole under it; each is replaced by its black end cap as a decal on the bumper, out of the length and the footprint, with a bias equal to its distance from the bumper face's centroid (a merged bumper face's centre is nearer the camera than an off-centre decal by up to that distance, and with the plain decal bias of 0.02 the second pipe vanished). **The model sedan is 1.61 m tall with the hood at 1.01** — from `EYE` that hood would hide 10 m of road instead of the 5.4 in `blindZone` and the level tips. From the cockpit only the hood is visible (the cabin cube covers the rest), so inside the own car is drawn lower by one height factor, `cabinK` 0.853 (the largest at which the hood stays under the sight line; `carCabinK` in `emitCarModel`, the wipers go down with it), while outside and in the side mirrors — their cameras are outside the cabin — it is the reference. **From the cockpit the own model is drawn without its greenhouse** (`g` on faces from `models.py`: glass, pillars, roof and window frames — above the window base between the windshield and rear-glass edges): the cube replaces it, the model's windows are not where the cube's windows are, and the frame faces looking into the openings passed the back-face cull, so on the first deploy the model's A-pillars and roof edge lay across the view from the wheel (#255). `cabin-check` `@render-cabin-own-body` collects every own-body face visible from the eye on five head turns and fails on any above the cabin sill (`MIR_H.y0`); `FAULT=greenhouse` turns it red. Coplanar faces of one material are merged (`dissolve_limit` 0.5°): unmerged, the bodies had 380–470 faces and level 1 cost +1.2–1.7 ms JS on a CPU×4 phone; merged and without the pipes, 173 / 162 / 279, polygons up to 27 vertices, concave ones included, so `carModel.scratch` holds arrays up to `MAX_POLY` 48 (phone CPU×4, level 1, same session against the first fit: chase JS 11.0 → 9.0 ms, cockpit 12.9 → 10.1, faces in the frame −20 %). `tools/blender/consts.mjs` exports the loft hull under the old name `CAR_HULL`: the cabin bake fingerprint must not depend on the body model. The world pass of `sortAudit` counts more crossings than with the loft (≈20 vs 4: the kerb edge over the neighbours' lower body, not gated).

Exterior look (2026-09-06): `MAT.paint/glass/chrome/plastic` go through the outdoor branch of `shadeCol` — `refl` mixes in the sky (`SKY_REF`, stronger on up-facing normals), `spec/shin` is a sun highlight from the view vector, `emit` (lamps) skips the lambert term; `sectionNormals` gives every loft section outward vertex normals once, and cars within 16 m get gradient-shaded flank faces (`n1/n2`, side edges only — roof/hood normals lean along z and the section doesn't know it), beyond 40 m no material at all (a `pow` per face showed in JS time). **Wall textures**: `wall/hedge/kerb` carry `tex` (`concrete` by default, `brick` on the beige walls, `hedge`), compiled by `pushBox` into tile coordinates in the **box's own frame** (`along`/`across`/`up`, absolute projections, so the pattern runs unbroken across the 3.5 m segments and brick rows are always horizontal) and laid by `texFace` as a second fill of the face with a repeating luminance tile (`texPattern`: white/black in the alpha, like the cabin grain; `TEX_PX` 128 px/m, brick 260×75 mm with light mortar, concrete noise + horizontal formwork joints — no vertical joints, the seam gate would read them as seams — and hedge leaf noise). Three rules paid for on level 1's 80 m wall: (1) **three mip levels** picked in `faceMode` by minification (`f.gk` holds the level, not a grain weight — `cockpit-shots --sweep` exempts `+tex` faces from the grain-toggle rule), each level's alpha re-scaled so its «sign × alpha» variance matches level 0 — plain averaging lost contrast and neighbouring segments on different levels met at a visible band; (2) **the tile is mapped per cell, not per face**: an affine map from three corners ignores perspective, and on a 3.5×6.5 m face at an angle each segment skewed the pattern its own way, leaving a vertical stripe at every seam (invisible on 10–20 cm cabin faces); `texFace` splits the face into ≤ 8×8 cells of ≤ `TEX_CELL` 140 px, projects each corner honestly and builds every cell's contour with `pathCam` (the expansion closes the hairline gaps between cells) — **under the base canvas transform**: path points are fixed by the CTM at `lineTo` time, and built under the previous cell's pattern matrix only the first cell of each face was ever filled; (3) the texture is a second fill of the whole face, and on a software Canvas the level-1 wall cost 51 → 40 fps, so `QUALITY[q].tex` is off from q3 while `edges` stay to q3. `look-check` `@render-wall-texture` pins `trainer_gfx=max` first — the headless governor reaches q3 in seconds and the check went red on the ladder, not on the picture.

**Cabin lighting**: in the cube the light is baked in Blender — sky above and dark ground, window lights at head height, a flat `AMBIENT` 0.35 of the material colour (physically the headliner faces the dark cabin and came out greyer than dark cloth), matte trims with specular 0.15 (the dash top caught the sky and went pale); everything below applies to the live layers and to the fallback. `cabinLit` (set around `emitInterior`, cleared in a `finally` so it can never leak into outdoor faces) switches `shadeCol` to interior lighting — ambient 0.48 (0.38 turned the dash into a black mass), no fog, a height-based occlusion term that darkens toward the floor, and the light comes **from the windshield** (`cabinLight`, set per frame in `emitInterior` from `fwd(car.th)` + up), not from the sun, so the dash and wheel look the same at any heading. On top of that sits the material model: `pushFace(v,n,col,bias,o)` takes `o = {mat, ao, n1, n2, img}`. `MAT` (matte/softtouch/leather/satin/gloss/cloth/rubber) is the *reflectance*, never the colour: a Blinn-Phong highlight from the view vector (`spec/shin`; leather `shin` is 6, not 14 — with six tube facets a narrow highlight falls between the edge normals and never shows), `ao` multiplies the ambient in niches (door pocket, handle cup, rear headliner), `n1/n2` are shading normals at the edges v0–v3 and v1–v2 and turn the face into a `createLinearGradient` — this is how a five-face roll, a six-sided pillar or the 24×6 wheel torus read as smooth; the geometric normal `n` still does the back-face cull, a shading normal there would drop silhouette faces — and `mat.grain` lays a procedural seamless tile (`grainPattern`: leather/cloth/rubber, periodic value-noise) through `ctx.transform` at `GRAIN_PX` 700 px/m. The tile coordinates come from the **body frame**, not from the face's own edges: `grainUV` (called from `pushFace` while `cabinFrame` is set) projects the face's v0/v1/v3 onto one of three body planes chosen by the dominant component of its body-space normal, and `grainFace` solves the affine map from those coordinates to the screen. With per-face U/V every part started the pattern at its own corner under its own angle, and headliner, roof rail and pillar each ran the weave a different way — the trim read as patchwork («текстуры криво друг на друга накладываются»). The plane choice cannot flicker: the normal is constant in the body frame. A degenerate affine (edge-on face) skips the pass. The earlier single screen-space noise pass read as monitor static, not as trim. Both extra passes skip near-clipped faces (their edge points are not the real corners). `MO` holds the common `o` presets (`pillar` = cloth × 6 sides, `round` = matte × 8, `stalk`). Instruments are the counter-exception: the speedometer needle, the wheel marks, the dome lens and the blinker repeaters go through `emitLit()`, which drops the interior mode for their faces, because under the cabin dimming they sank into black — losing the very readouts added to make the steering angle and gear readable. The dial itself is an `img` face (`dialCanvas(sel)`: four cached canvases, current gear letter green, scale 0–60 shared with the needle through `DIAL_A0/DIAL_SPAN/DIAL_MAX`, gear row in the upper half because the hub hides the lower); its backing quad is cabin-shaded `CAB.DARK`, so the image square does not stand out on the binnacle. `tools/cockpit-shots.mjs` (playwright-core from a temp dir, see its header) shoots five head poses plus chase, runs `sortAudit` on 8 yaws, the demo regression, `frameCost` and (with `--sweep`) the head-turn mode-toggle count, and exits 1 on any failure — run it after touching the cabin: desktop ≈3 ms JS, phone landscape ≈3 ms.

**Slope / эстакада**: zones in `level.ramps` (`rampZone`/`deckZone` factories, compiled with local axes + bb). Physics is one gravity term in `stepCar` **before** the mode branches, so brake and P cancel it in the same substep; creep honestly loses only to grades ≥16 % (`creepAccel` 1.5 vs g·sinθ) — the training ramp uses 0.17. `car.roll` is the rollback meter (exam threshold 0.3 м), reset when the car moves with its gear. Rendering: `toCam` warps **every vertex** by `groundH(-x, z)` behind the `RAMP_ON` fast-path — world, shadows, decals and marks climb consistently; the deck is painted by flat decals (`drawRampDecks`) that the warp lays onto the slope. The ramp is a structure on flat ground — `screenToGround` and collisions stay 2D. **The car is the exception: it is a rigid body and must not be warped vertex by vertex.** While the nose is on the 0.17 grade and the tail is still flat, per-vertex `groundH` shears the loft and the cabin diagonally, and from the cockpit the dash — a metre ahead of the eye — rises 0.17 м *above* it and stands across the view (the owner's «машина от первого лица пропадает в текстурах»); at the deck edge `groundH` is discontinuous, which is where the black shards came from. **Traffic flow** (`traffic:'city'|'yard'` on a level; 26–32). Three scripted statists in the whole file — and none at all on the exam, whose two `yieldZones` therefore could never fire, because the detector iterates `level.actors` — meant the city never asked the only question it exists to ask: whom do you let past. `trafficInit()` puts cars on closed loops built by **the same router that draws the player's green line** (`cityRoute` over `city.graph`), so a flow car never steers: it advances along its polyline by arc length (`trafPose`), which makes cutting a kerb or crossing onto the oncoming half geometrically impossible and leaves only longitudinal behaviour to get right. Lessons paid for:
- **Loops turn right** (two of them: the west rectangle N1-N7-N6-N2 and the east one through the ring). A chain of left turns across oncoming traffic locks a junction solid in dense flow.
- **`cityRoute`'s first and last point is the raw waypoint** — the street *axis*, not the lane centre. With them every loop stepped onto the centre line, and two opposing cars spawned in the same spot; `trafPath` drops them, and consecutive legs then join lane-end to lane-start with no seam.
- Longitudinal control (`trafBlock`) is three rules: a **same-direction car ahead always blocks** (a queue cannot be resolved by priority — the rear car drove into the leader), a **stopped** car always blocks, and a **crossing** car is resolved by *who reaches the conflict point later*. A static index priority let a car drive into another's flank: it saw the priority car sideways, and the priority car did not see it at all. `trafConflict` adds a pair check walked along **both cars' own routes** — a straight-line prediction inside a junction is wrong for both at once, and a merge was noticed 3 m before contact, with no braking distance left.
- **The corridor gates treat the other car as a box, not a point** (`ext()` projects its half-extents onto my axes): a car standing across a junction has its centre 2.5 m off my lane and its body right on it, and by centres the flow drove into its side.
- **Traffic yields to the player and holds an extra 2.4 m**: `_hitByPlayer` latches on any OBB overlap no matter who moved, so a flow car nudging a parked player burned the player's attempt.
- **The flow is created after `computeIdealPath`** (in `loadLevel`), because the headless replay never calls `actorsTick` and cars created earlier stand across the ideal line. `tools/level-audit.mjs` advances `actorsTick` itself for the same reason — otherwise the показ hits frozen traffic and every `gap` chip reads 99 s.
- **`trafficGap(u,v,d)` replaced `actorNear`**: with a stream there is always a car nearby, so the «уступи» card would hang until the timeout, and the car queued behind you in your own lane is not a hazard at all. The gap is **seconds to the nearest hazard at a point 6 m ahead of the car** — at a yield sign the driver stands *before* the road, and measured at his own position the flow always passes clear — and the hazard's arrival is walked along **its own loop**, since on a ring a straight line misses by the whole arc. Every yield phase is a pair now: «стой, поток идёт» with a `gap` chip counting seconds down, and «окно есть — выезжай». One phase flipped back and forth as cars came and went.
- **The «front» clearance is not «who is ahead».** `lastClear.front` folds in the front-corner diagonals, and in the kerb lane of any city street the right diagonal hits the pavement kerb: `front = 1,12 м` with nothing in front. The demo's «do not ram the flow» brake used it and stood still on every frame on levels 27–31 — `computeIdealPath` timed out every segment, the live «демонстрация» button did not move the car at all, there was no ideal line, and `demo-vio` was clean only because nothing drove (#154). - **A yield is never owed to the car following you in your own lane.** The yield detector projects the other car at its nominal `sp`; a flow car queued 9 m behind a player crawling up to the «уступи» line was «projected» into his rear and fined a непропуск (fatal on strict levels, 5 баллов on the exam) — the same exclusion `trafficGap` already had (behind along my heading, heading within 60°) now sits in `violationsTick`, guarded by `@traffic-yield-follower`, with `@traffic-yield-cut-in` keeping the real case fined. The level-30/31 demos also stop before their yield zones now (`uGte 56`, `vGte −17.5`): with the old ends they rolled into the zone at 1.4 m/s.

- A `yieldZone` latches per **pair** (`y._hit`, zone × actor, 8 s), not per zone: with a stream, one latch meant the first непропуск made every later one free.
- **A loop waypoint that lies on a roundabout** is joined to the next leg by `ringArc`, never by a straight line: `cityRoute` ends a leg whose target is inside a ring at the ring entry (for the player's line the island is not a destination), and `trafPath` used to stitch that entry to the next leg's start across the island — flow cars drove straight through the roundabout's centre on every city level (loop B's `{u:90,v:0}` is on ring N4). `traffic-check` skipped every sample within a node's radius, so it never saw it; `@traffic-flow-island` now fails any flow car closer than `round − 6` to a ring centre, before that skip.

**Провал попытки** (`strict:true` on levels 23–31; the exam scores points instead): a gross violation cancels the whole run, the way it does in life. `PENALTIES` carries two flags — `fatal` (collision with a car/wall/sign/actor, непропуск, red light) ends the attempt immediately, `hard` (встречка, стоп-линия, сплошная) is a strike: the first shows a red `k-stop` card naming the rule, the second fails. `attemptVio`/`failAttempt` live next to `examPenalty` but never both fire — `vio()` routes to the exam first. `hitPenalty` is the single entry for collisions and is **muted during demos** (the показ would burn the player's attempt). **A kerb touch is counted but is not a strike**: a city street is 6.6 m wide with a metre of clearance each side, and a novice will scrape one — cancelling the run for that drives away exactly the player the trainer is for. `levelFailHTML` shows cause + the rule + the log + an «отработать приём» button from `EXAM_TRAIN`; `doAct('resume')` re-shows it, because `game.done` freezes physics.

The exam has no `goal` and no `marks()`, so «угол к цели» is blank and nothing else in the world marks where a command is meant to be executed. The beacon is training-mode only — the silent inspector plants no landmarks. **The route line and the maneuver zone are not**: the exam was the only level with nothing on the asphalt (no demo ⇒ `level.idealDraw` is null), and both now draw in **both** modes through `drawExamNav`, deliberately **not** via `drawMarks` — `examInit` kills `opt.marks` in memory for the real mode, and the inspector's command must still be visible; in life he says where to go and repeats it, and what the exam checks is driving, not memory for the route. `examLegBuild` (throttled to `EXAM_LEG_T` = 0,35 с, rebuilt at once on a stage change) routes car → current `at` → next `at`, trimmed to `EXAM_LEG_MAX` = 160 м and drawn through `buildIdealDraw` so there is no per-frame allocation; a stage whose `at` is a roundabout centre routes **through** the ring to the next command instead (the island is not a destination, and with both ends on the ring `cityRoute` had nothing to search — the line vanished exactly where the player picks an exit). `examZoneOf` resolves the current stage's footprint out of the same geometry the detectors use — pocket, ramp stop line, junction patch, U-turn zone — and for the U-turn also paints the tram bed edges and the full-lock arc (`sweep(CAR.maxSteer).R` = 3,84 м) that answers «где разворачиваться» in one picture. **Pocket geometry lives in `EXAM_POCK` only.** The blue dashed pockets used to be painted from their own numbers in `build()` and had drifted 6–9 м from where the stage accepted them (painted v=−50/−38, accepted −56/−47; the second draw did not overlap at all): the player parked dead centre of the drawn rectangle and «остановка у тротуара» never completed. Command, acceptance predicate (`inPocket`) and paint now all read one table. **Commands must name streets the way the plates do** — «по проспекту Ленина», not «по проспекту» — and the `short` form must carry the direction («налево на Садовую»), since it is the only form shown between 10 and 28 м. Violation detectors are checked synthetically: `tools/exam-check.js` → `examCheck()` (turn zones, blinker), `detectorCheck()` (15 cases on its own fixture — every violation code with a positive and a negative case) and `routeCheck()` (walks all three routes stage by stage, catching a stage that never completes or one that completes instantly). The `dir` filter of a turn zone is an *entry* gate only; checking it every frame once dropped every exam penalty for turning without a signal. `examFail` is the game's first losing end: `game.done` + fail screen, the `doAct('resume')` trap re-shows the protocol, Escape during the exam asks «прервать?» instead of help. The protocol embeds an SVG mini-map of `exam.trail` (recorded every 0.35 м in `examTick`) with red dots at penalty positions and «отработать» buttons (`EXAM_TRAIN` maps code→level, `data-act="train:N"`). Progress: `progExam` writes `{n, passed, bestScore}` plus a per-mode `{train, real}` record — `{n, passed, routes[3], bestScore}` — on top of `trainer_progress` without breaking old records (entries without those fields are honestly counted as rehearsals). Before that split a pass in «тренировочный», with markers, clearances and an on-the-spot debrief, went into the same counter as a real one, so «сдал экзамен» meant nothing; **«готов» now requires a pass in the real mode on each of the three routes** (`examRuns()`), because three passes of one memorised route prove nothing — `exam.routeId` comes from `examRoute()` tagging the array it returns. `examNextHTML` says on the win screen what the run was worth and what is left. because that store is keyed by **level name** and the name carries the number, `PROG_RENAME` migrates the exam's old key once — inserting levels 27–31 would otherwise have wiped every player's exam record. `examReadiness()` = % of clean runs over `EXAM_SET` (17 levels), shown on the start screen and level picker with `weak` card highlighting, with the real-mode route count on a second line. The **corner route map and the briefing draw the same routed polyline** as the asphalt line (`examMapPath`, cached per run) with street labels, the car as a heading triangle and the stage's turn glyph — the old map joined the command points with straight dashes across the blocks and answered nothing. The briefing re-opens on a tap on that map, from «Маршрут и команды» in the ≡ menu and from the abort dialog, with passed stages ticked off and the current one highlighted: it used to be shown once before the start, and `Escape` mid-exam offers to abort, so a player who forgot a stage had nowhere to ask. **`navCheck()` in `tools/exam-check.js`** guards the layer over 8 route draws: a stage with no routable path, a line point off the asphalt or on the roundabout island, a line on the oncoming half, an unresolvable zone, a pocket centre that does not complete its stage, a street named in a command that the city does not have, and a plate standing on the carriageway. **learner.js** (repo root, not deployed): the scripted «ученик» — reads the coach card every 100 ms **structurally** (`.cm` action text, `.cw` wheel pictogram, `.cgear` target gear, `.cg` goal chip with its `done` class and «цель X° · сейчас Y°» numbers) plus the HUD «угол к цели» (`#angVal`) and clearances, and does only what they say. Run in the page console: `const stop = learnerStart()`; `window.learnerLast` shows the branch it took on the last tick. It tests the **teaching texts**, not the physics. Stop-words are searched only in the action text — the chip «стоп у голубой линии» is a landmark, and reading it as a command parked the learner at the start line forever. Composite cards («Ты в зоне, но … Дальше: …», the P-note) are followed by their «Дальше:» part; «доверни/подровняй» comes from the prefix. Novice rules the text never states but every maneuver needs: reverse at a crawl, turn the wheel to lock at a standstill (the demo brakes while it turns too — winding from lock while rolling adds ~20° of arc), stop-and-shuffle in a tight pocket, back off after a touch, straighten under a toast. Traps paid for: JS `\b` is ASCII-only — `/зон[а-я]*\b/` never matches after Cyrillic; the `ang` chip is |heading − goal axis|, so a turn's goal is `target:0, dir:'down'`, not «90 up»; a left U-turn's heading goes 0 → −180 and wraps to +177 — window it from both sides. Hint-chain defects the learner exposed and that are now fixed live in git history (7319f5a, 31cb3c6). Known variance: in the 2.3 m pocket it occasionally times out shuffling the last 5–8°, and on the city levels 28–31 it wanders inside a 6.6 m street — its steering is bang-bang with no lane-keeping, so on a road with a metre of clearance each side it scrapes kerbs and arrives at the goal zone crooked. Treat a city timeout as a signal to read the card chain, not as proof the level is unsolvable: the demo, `detectorCheck` and `routeCheck` cover solvability. It still earns its keep there — it found that «встать в правую полосу» as words steers a novice into the kerb (a goal chip needs a *number*), that a U-turn phase chain without a positional bound loops through the whole circle, that a stopped car was being fined for непропуск, and that a phase chain must cover «проехал зону» or the card tells you to stop where there is no zone. When testing a fresh `index.html` in the browser, load it with a cache-buster (`?nocache=<ts>`) and check `fn.toString()` for the edit's marker — the static server's heuristic caching once had a whole test pass confirm stale code.

**Лендинг: пять вопросов посетителя.** Страница обязана отвечать на пять вопросов по порядку
их чтения: что это, кому и в каких ситуациях, какой результат, почему стоит смотреть дальше,
что сделать сейчас. Аудит 17.09.2026 нашёл, что из пяти закрыты были два — и оба провала были
структурными, а не текстовыми.

**Прикреплённый герой не имеет права молчать.** `.hero` — это «сколько прокрутки уходит на
показ»: `park.js` считает её как `hero.offsetHeight − stage.offsetHeight`, а копия (H1, лид,
кнопка) уходит уже на 10 % этой прокрутки. При 240vh после первого экрана шло 1260 px, то есть
1,4 экрана без единой строки текста, заголовка и цифры — кто не понял с первого кадра, уходил
здесь. Высота и длина ленты реплик — **связанная пара**, и считается она в пикселях прокрутки
на реплику: порог читаемости 110 px на десктопе и 90 px на телефоне, примерно один щелчок
колеса. Второй, более злой дефект того же места: `paint` раскладывал прогресс линейно по точкам
пути, поэтому доля прокрутки у реплики равнялась **длине её участка траектории**. Замер показал
«Точку 2» (доворот на 45°, главный ориентир всей методики) с 30 px из 675, а «Готово» не
показывалось вовсе — прокрутка кончалась раньше. Лечится не высотой, а равными окнами на реплику
(`indexAt`/`STEP_SPAN`). Гоняй `tools/hero-tape.mjs` после правки высоты `.hero`, списка `STEPS`
или разбивки `PATH` по фазам: он печатает px на каждую реплику и молчащую прокрутку и падает на
пробитом пороге. Глазами это не проверяется — сам знаешь, что написано в карточке, и успеваешь
прочитать то, чего новичок не увидит. Точность замера стоила двух правок самого инструмента:
границы реплик уточняются делением до 1 px, и каждая позиция прокрутки ждёт **двух кадров
rAF**, а не таймера — `park.js` перерисовывает сцену внутри `requestAnimationFrame`, и с
фиксированными 10 мс одна и та же сборка давала минимум от 101 до 110 px при пороге 110.
Флаки-гард хуже отсутствующего: он учит не доверять проверке.

**И у героя есть второй режим — `prefers-reduced-motion`.** Там `paint` ставит `open = 1`
сразу, а `.hero.open` гасит копию: H1, лид и кнопка «Начать тренировку» были невидимы, на
первом экране оставались стоящая машина и карточка «Готово», единственным входом — «Играть» в
шапке. Блок `@media (prefers-reduced-motion: reduce)` обязан стоять **последним в `<style>`**:
правила для телефона (`max-width:899px`) задают `.hero-coach { top }` ниже по каскаду и при
равной специфичности победило бы то, что написано позже. Возвращать нужно и копию, **и
затемнение** (`.hero-scrim`) — без него текст ложится на машины и на линию траектории, причём
проверка перекрытий по геометрии остаётся зелёной, а читать нельзя. Правку героя смотри в
обоих режимах и на кадре, а не только в цифрах.

**Результат называется величиной, которую продукт правда считает** — готовность к экзамену
(`examReadiness`: доля чистых заездов по 17 уровням `EXAM_SET`) и лучшая точность дриллов в
сантиметрах (`bestErr`). Обещать сдачу нельзя: этого продукт не контролирует. Строка доверия на
странице — личная история автора, а не звание: «искал такое приложение и не нашёл, поэтому
написал сам» проверяемо, «аналогов нет» читателю проверить нечем и voice-карточка запрещает
сравнение через отрицание.

**Landing clips**: `tools/landing-clips.mjs` records a level's демонстрация in a headless browser and encodes `landing/public/clips/<name>.{mp4,webp}` (h264, no audio, ~100 КБ each, poster via `cwebp` — homebrew's ffmpeg has no webp encoder). **Аккаунт, аналитика, пейволл** (`docs/ACCOUNT.md`, `docs/ANALYTICS.md`, план `.ai-factory/plans/account-auth-analytics-paywall.md`). Вход через VK ID и Яндекс ID (порядок кнопок задан 149-ФЗ, а не деплоем), гость — это просто «Поехали». Сервис — `server/account.py` (stdlib + SQLite) на vdsina за `location /api/v1/`, зеркало 194 проксирует туда же; флоу один на все поверхности — `start → callback → claim`, как Mini App-флоу spark, плюс `nonce` вкладки: `sid` виден в адресе возврата `/play/#auth=<sid>`. Правила, которые легко сломать: (1) интерфейс входа появляется только по `window.AUTH_PROVIDERS`, аналитика — только по тегу `/rb/script.js`; обоих вставляет веб-деплой из `.deploy.env` (`AUTH_PROVIDERS`, `RYBBIT_SITE_ID`), поэтому локально, в гейтах, в билде ЯИ и на старом зеркале их нет и запросов нет; (2) адрес API абсолютный, как у отзывов, — гейты мокают ровно его; (3) SW пропускает `/api/` и `/rb/` мимо кэша — ветка ресурсов cache-first закэшировала бы `/me` с покупками навсегда (`@dist-sw-api-bypass`); (4) **`level_start` и замок пейволла живут в `openLevel`, не в `loadLevel`**: `loadLevel` зовут старт страницы, смена потока и режима экзамена, редактор и все гейты — в нём воронка считала служебные перезагрузки попытками (#181), а замок уронил бы гейты; новый пользовательский вход в уровень обязан идти через `openLevel`; (5) слияние прогресса делает только сервер (`best*` — min, остальное — max, поэлементно), клиент шлёт свой `trainer_progress` и кладёт итог, но не поверх записи, сделанной пока шёл ответ; (6) окно входа в iframe открывается синхронно в нажатии — после `await` его режет блокировщик; (7) refresh ротируется: перед обменом он перечитывается из хранилища, а 409 `rotated` — гонка вкладок, не выход.
