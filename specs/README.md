# Сценарии поведения

Правило, по которому тренажёр судит игрока, живёт в трёх местах: в голове, в коде детектора
и в проверке инструмента. Сценарий — единственная форма, которую читают все трое: владелец
узнаёт своё требование, код получает проверяемое условие, а инструмент — числа, по которым
он падает.

## Где что лежит

| Каталог | Что описывает |
|---|---|
| `collision/` | что считается касанием и чего оно стоит |
| `clearance/` | зазоры, слепые зоны, габаритные ориентиры |
| `city/` | разметка, знаки, светофор, маршрут по полосам |
| `traffic/` | поток машин: дистанция, приоритет, окно, гудок, плавность курса, трамвай (`tramvai.feature`) |
| `exam/` | баллы регламента, провал, режимы экзамена |
| `mt/` | механическая коробка и её экранная часть |
| `render/` | вид сцены: рёбра, текстуры, зеркала — только `@ui`, судья — пиксели кадра |

Имя файла — тема, а не номер: `nepropusk.feature`, `stop-liniya.feature`.
Один файл — одна функция, 3–8 сценариев.

## Как пишется сценарий

```gherkin
# language: ru
Функция: Непропуск

  Кого тренажёр наказывает за непропуск и по какому признаку.

  Ссылка: регламент 2026, аварийные ошибки; калибровка tools/yield-sweep.mjs

  @domain @traffic @traffic-yield-tca
  Сценарий: Непропуск считается по моменту наибольшего сближения
    Дано уровень "31 · Косой перекрёсток"
    И машина стоит в точке (-76.35, -11) курсом 0°
    Когда скорость машины 2 м/с
    И проходит 1 секунда
    Тогда нарушений нет
```

Обязательны первая строка `# language: ru` и блок `Ссылка:` — по нему через полгода видно,
откуда требование: замечание владельца, пункт регламента, ПДД, коммит, задача на доске.

## Теги

Три вида, все три нужны.

- **вид** — `@domain` (исполняется `tools/gherkin-run.mjs`) или `@ui` (связан по коду с
  проверкой в инструменте);
- **область** — `@collision`, `@clearance`, `@city`, `@traffic`, `@exam`, `@mt`, `@render`;
- **код требования** — свой у каждого сценария: `@<область>-<тема>-<что>`, например
  `@traffic-yield-tca`, `@mt-clutch-gear1`.

**Код неизменяем после появления.** Он стоит в проверке инструмента и в чек-листе; переименуешь —
связь порвётся молча, и `tools/gherkin-check.mjs` покажет сценарий без проверки.

## Числа в шагах

Берутся из правила, из регламента или из замера, а не из текущего вывода кода. Сценарий,
списанный с реализации, проходит всегда и не ловит ничего — ради этого всё и затевалось.

## Как проверяется

```bash
PW_DIR=/tmp/pw node tools/gherkin-run.mjs        # исполнить @domain-сценарии
node tools/gherkin-check.mjs                     # связь сценарий ↔ проверка
node tools/gherkin-check.mjs --list              # таблица связей
node tools/qa-checklist.mjs                      # пересобрать docs/qa-checklist.md
```

`@ui`-сценарий не исполняется, но обязан иметь проверку: код требования ставится в её имя.

```js
check('со сцеплением включается 1-я (@mt-clutch-gear1)', ...)
```

Гейт нашёл сценарий без проверки — это повод написать проверку, а не снять тег.
