# Экзамен помечался пройденным после первого же провала

**Date:** 2026-09-14 17:05
**Files:** index.html
**Severity:** medium

## Problem

В выборе уровней карточка «32 · Экзамен» получала галочку ✓ и класс `pass` после
первой же неудачной попытки. Игрок видел уровень пройденным, не сдав его.

## Root Cause

Карточка решала «пройден» по факту существования записи: `const pg=progOf(l.name)`
и дальше `pg ? ' ✓' : ''`. Для всех уровней это верно — `progAdd` зовётся только из
`win()`. Но у экзамена запись заводит ещё и `examFail` через `progExam(false)`:
он считает ПОПЫТКИ, и это правильно, просто предикат «есть запись» перестал
совпадать с «пройден», когда появился второй писатель прогресса.

Класс дефекта: проверка на существование вместо проверки по смыслу. Пока писатель
был один, они совпадали, и расхождение появилось молча.

## Solution

`progPassed(name)` рядом с `progOf`: у экзаменационной записи (`p.passed !== undefined`)
смотрит `p.passed > 0`, у остальных — `p.n > 0`. Карточка берёт галочку и класс из него,
а строку статистики по-прежнему показывает при любой записи: «попыток N» — полезная
информация. `progLine` при `p.passed === 0` печатает «попыток N · ещё не сдан» вместо
«настоящих маршрутов 0 из 3».

## Prevention

- Как только у хранилища появляется второй писатель, все предикаты «есть запись»
  надо перечитать: они молча меняют смысл.
- Признак «пройден» должен опираться на поле, которое означает именно прохождение,
  а не на присутствие объекта.
