## Контекст: что измерено (Chrome, этот Мак, 1440×900 CSS, DPR 2 = 2880×1800)
| Сценарий | Старый салон 4d3ea3d | Новый салон 755bcfa |
|---|---|---|
| GPU-Canvas, 2880×1800 | 120 fps, JS 2,5 мс | 120 fps, JS 3,6 мс |
| GPU-Canvas, 5120×2880 | 120 fps | 120 fps |
| Программный Canvas (`--disable-gpu`) | **15 fps**, p95 70 мс | **12 fps**, p95 88 мс |

Программный Canvas по подсистемам (новый салон): без зерна 21 fps → без градиентов 46 → без зеркал 54 → без обводки граней 86 fps (p95 12,5 мс). Операций за кадр: fill 1950, stroke 2004, clip 308, createLinearGradient 244, save/restore 429, проходов рендера 6 (основной вид ×2 + три зеркала). Вывод: JS не узкое место (3,6 мс); тормозит растеризация — число вызовов Canvas × площадь Retina. У владельца Canvas без GPU (Яндекс Браузер / выключенное ускорение) — план обязан держать 60 fps именно там, GPU-путь при этом не должен потерять вид.

**Второй симптом (владелец):** при повороте головы из салона «текстуры моргают». Кандидаты в коде: (1) `createLinearGradient` с совпавшими концами (грань ребром) по спецификации **не рисует ничего** — грань пропадает на кадр; (2) грань, пересёкшая ближнюю плоскость, переключается градиент → плоский цвет и обратно (`!behind`); (3) плитка зерна без мип-уровней при сильном уменьшении (торпедо под скользящим углом) шумит при движении; (4) зерно включается/выключается по порогу площади 12 px². Всё это — фаза 1, до оптимизаций.

Ограничения: вид салона после #60 сохраняется (скриншоты до/после фазы — попиксельно близки на GPU); `sortAudit` салона 0; демо 18/0; уличный вид не меняется; зеркала остаются перетаскиваемыми (`mirrorAt/mirrorRects`); `CAR/EYE/HOOD_*` не трогаются.
