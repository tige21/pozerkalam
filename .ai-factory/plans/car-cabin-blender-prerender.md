## Что есть в коде (разведка 02.10)

1. **Глаз не смещается.** `fpEye()` (index.html:7086) берёт константу `EYE` (1281), взгляд назад —
   поворот `headYaw` на 150°. Значит куб, отрендеренный из `EYE`, точен при любом повороте головы,
   FOV и на эстакаде: куб жёстко связан с кузовом, как и `carLift`.
2. **Точка вставки.** `drawSceneInto` (7708): мир → `flushFaces()` (если `inside`) → свой кузов
   `emitCarMesh(…, {own:true})` + `emitInterior` + `emitCornerPosts` под `carRampUse` → `flushFaces()`.
   Салон — `emitInterior` (2180) = `emitCabinSkin/Shell/Rear/Dash/Wheel`.
3. **Живые части сидят внутри запекаемых функций и на локальных числах.** Щиток — `emitCluster`
   (2037: центр `-0.36, 0.985, 0.552`, `Rd 0.056`), повторители поворотников — в `emitDash`
   (1826–1830), рычаг — `emitSelector` (2053, ходит по `car.sel`), планка салонного зеркала — в
   `emitDash` (1836–1853, наклон `mirAdj`), руль — `emitWheel` (2058: `WC=[-0.36,0.90,0.50]`,
   наклон 24°, `Rw 0.185`). Чтобы Blender и игра читали одни числа, их надо вынести в константы.
4. **Салонное зеркало видит салон из своей точки** (`mirrorCam('center')`, 7096: z ≈ 0,33, смотрит
   назад, поворот `mirAdj`) — ему нужен свой куб; сам проход — `renderMirrorInto` (7799).
5. **`CAR_HULL` (5823) строится из `CAR_ST`** (ширина и z станций) и питает столкновения
   (`polyMTV`, 5876/5904), рамку `drawRefs` и угловые столбики. Кузов из Blender — только картинка:
   `CAR_ST` остаётся источником следа, модель обязана с ним совпасть.
6. **Огни своей и чужих машин** — жёстко заданные квады в `emitCarMesh` (2189): фары/фонари на
   z ±2,226, аварийка `HAZ_LIGHTS`, решётка `carGrilleCanvas`, номера `plateCanvas`.
7. **Инструменты открывают игру через `file://`** (все, кроме `hero-tape` и `yandex-check`):
   внешняя картинка там закрывает канвасу `getImageData`, и проверки пикселей падают. Значит
   картинки — только `data:` внутри `index.html`.
8. **`tools/mirror-script.sh` копирует содержимое любого `<script…>`**: ассеты в
   `<script type="application/json">` уехали бы в `codegraph-src/index.js`. Поэтому блок ассетов —
   `<div id="assets" hidden>` с `<img>` и `<template>`, до основного скрипта. `tools/mutate.mjs` ищет
   `<script>` около `"use strict"` — блоку не мешает. CSP прода пускает `img-src data:`, хэши
   считаются только по инлайновым скриптам; SW кэширует страницу целиком — отдельных файлов нет.
9. **Среда:** `brew` есть, Blender — нет; Pillow, numpy, `cwebp` — есть; scipy — нет.
10. **Исходники весят 41 МБ PNG.** В git — сжатые WebP q95 (≈5–8 МБ), PNG — вне git (`.gitignore`);
    `clean.py` читает WebP.

## Решения
- Салон — 6 граней куба из `EYE`, рендер Cycles, окна прозрачные. Рисуется после мира как
  изображение по ячейкам (приём `texFace`: ≤12×12 ячеек, `pathCam` с раздвижкой, пропуск ячеек за
  ближней плоскостью), в кадре кузова и с подъёмом `carLift`.
- **Глаз неподвижен — значит порядок «куб, потом живые слои» точен**: что закрыто из `EYE`, закрыто
  при любом повороте головы. Правило: каждый живой слой целиком виден из `EYE`; Blender-скрипт
  проверяет это лучами и падает, если слой чем-то закрыт.
- Порядок кадра в салоне: мир + свой кузов снаружи (капот, корпуса зеркал) + угловые столбики →
  `flushFaces` → куб → щиток → рычаг и планка зеркала → руль → `flushFaces`.
- Старый салон (`emitInterior`) остаётся путём отказа: пока картинки не распакованы, при сбое и по
  `?cabin=old`.
- Разрешение граней: перёд 2048, бока 1536, зад/верх/низ 1024; на `MOB` при загрузке вдвое меньше
  через канвас, исходник освобождается.
- Кузов снаружи: модель из той же сцены, ≤400 граней вблизи (своя и соседи ближе 20 м), нынешний
  лофт 20–45 м, коробка дальше 45 м (`TRAF_LOD`). Зоны огней — именованные грани модели.
- Бюджет `index.html` ≤ 2,2 МБ (сейчас 775 КБ).
