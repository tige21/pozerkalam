## Решение и почему именно так

```
браузер ──POST /api/feedback (JSON)──▶ nginx pozerkalam.space (vdsina, РФ)
                                        ├─ limit_req 6/мин на IP, тело ≤ 1 МБ
                                        └─ proxy_pass 127.0.0.1:8787
                                                       │
                                        Python-сервис (stdlib, Debian 12 / 3.11.2)
                                                       ├─ валидация + honeypot
                                                       └─ sendMessage + sendPhoto
                                                              │ HTTPS_PROXY
                                                              ▼
                                                   tinyproxy на боксе 194 (Frankfurt)
                                                              │
                                                              ▼
                                                       api.telegram.org
```

### С vdsina нет прямого доступа к api.telegram.org

Это не предположение и не наша находка «на всякий случай»: у соседнего проекта spark
это уже измерено и задокументировано (`~/Documents/projects/spark/docs/TELEGRAM_BOT.md`,
замер от 2026-07-16):

| Путь | Результат |
|---|---|
| через прокси 194 | HTTP 200 за ~0,3 с |
| напрямую (переменные прокси сняты) | **таймаут 15 с, соединения нет** |

Telegram недоступен из РФ-хостинга. Прод-бот spark отвечает **только** потому, что
`HTTPS_PROXY`/`HTTP_PROXY` указывают на tinyproxy на боксе 194 (Frankfurt) — это тот же
`194.5.65.182`, что держит старое зеркало игры и доску Vikunja, доступ к нему по ssh уже есть.

**Следствия для нас:**
- сервис читает `HTTPS_PROXY`/`HTTP_PROXY` из своего env-файла; `urllib.request` уважает эти
  переменные сам — своего кода для прокси не нужно;
- `NO_PROXY=api.telegram.org` ставить нельзя ни при каких обстоятельствах — это ровно та
  «оптимизация», которая уводит канал в офлайн;
- канал зависит от бокса 194. Он и так уже несёт старое зеркало и Vikunja, так что новой
  точки отказа не появляется — но она должна быть видимой (см. self-check в T1).

**Токен не попадает в `index.html` ни в каком виде.** Три причины, каждая самостоятельно достаточная:

1. `index.html` отдаётся всем — токен в нём равен токену у всех. Бот
   `@spark_adminfeedback_bot` общий с проектом spark: утечка бьёт по двум проектам сразу
   (чтение чужих сообщений, подмена вебхука, отправка от имени бота).
2. Текущий CSP уже это запрещает: `connect-src 'self' https://mc.yandex.ru https://*.mc.yandex.ru`
   — запрос на `api.telegram.org` отвалится молча, без ошибки в UI.
3. Прямой вызов нечем ограничить: публичная кнопка «отправить что угодно в мой телеграм»
   без лимита частоты и фильтра.

**Проверено на месте (реконессанс, а не предположения):**
- бот жив: `getMe` → `Spark Feedback` / `spark_adminfeedback_bot`, вебхук не установлен;
- `getUpdates` → 0 обновлений, **chat_id взять неоткуда** — нужен `/start` от владельца (T0);
- сервер `vdsina`: Debian 12, Python **3.11.2**, node нет → сервис на stdlib, без зависимостей;
- `.deploy.env` в `.gitignore` (строка 3, подтверждено `git check-ignore`);
- ловушка nginx из CLAUDE.md действует: `add_header` внутри `location` отключает серверные —
  новый `location /api/feedback` **обязан** содержать `include snippets/pozerkalam-headers.conf`.

## Контракт эндпоинта

`POST https://pozerkalam.space/api/feedback`, `Content-Type: application/json`, тело ≤ 1 МБ:

```json
{
  "kind": "bug|idea|note",
  "text": "…",                        // 10…2000 символов, обязательно
  "contact": "…",                     // ≤120, необязательно
  "hp": "",                           // honeypot: непустое → 200 ok, но ничего не шлём
  "shot": "data:image/jpeg;base64,…", // необязательно, ≤700 КБ
  "ctx": { "level": "…", "li": 7, "build": "…", "gearbox": "AT", "cam": 0,
           "q": 0, "gap": 16.4, "js": 3.1, "dpr": 2, "screen": "1440x900",
           "mob": false, "runs": 12, "t": 143.2, "ua": "…" }
}
```

Ответ `{"ok":true}` либо `{"ok":false,"err":"<код>"}`. Коды: `bad-json`, `short-text`,
`too-long`, `rate`, `tg-fail`. `{"dry":true}` — валидация без отправки (для смоука деплоя).

Формат сообщения в Telegram (первая строка — тег, по нему отделяется от spark):

```
#позеркалам #баг
Уровень 8 · Параллельная слева · АКПП
Сборка a1fde231 · Chrome 141 · 1440x900@2 · q0 · 58 fps
Контакт: @nick

<текст игрока>
```

Скриншот уходит вторым сообщением (`sendPhoto`, подпись — только тег и уровень):
лимит подписи 1024 символа, а текст может быть длиннее — при склейке он бы обрезался молча.

### Фаза 1 · Сервер: приёмник отзывов

- [ ] **T0b. Адрес tinyproxy на боксе 194.** Порт в документации spark не записан. Взять с сервера:
  `ssh assistant-box 'grep -E "^(Port|Listen|Allow)" /etc/tinyproxy/tinyproxy.conf'`, либо из
  прод-`.env` spark на vdsina (`grep HTTPS_PROXY /opt/spark/docker/.env`). Проверить, что vdsina
  входит в `Allow` — иначе добавить и перезапустить tinyproxy.
  Результат → `TG_PROXY=http://194.5.65.182:<порт>` в `.deploy.env`. **Блокирует T8.**

- [ ] **T1. `server/feedback.py`** — HTTP-сервис на stdlib (`ThreadingHTTPServer` + `urllib.request`),
  слушает `127.0.0.1:8787`. Токен, chat_id и адрес прокси читает только из окружения
  (`TG_TOKEN`, `TG_CHAT_ID`, `HTTPS_PROXY`); без токена или chat_id — `ERROR` в лог и выход
  с кодом 1, чтобы systemd не притворялся, что всё работает.
  - **Self-check на старте:** один `getMe` через прокси, результат в лог
    (`INFO telegram доступен: <username>` / `ERROR telegram недоступен: <причина>`).
    Без него смерть tinyproxy на 194 выглядит как полностью здоровый сервис — ровно та беда,
    которую spark описывает словами «бот немеет, выглядя живым». Сервис при этом **не падает**:
    приём отчётов продолжается, неотправленное пишется в `journal` с полным текстом,
    чтобы отзыв игрока не пропал.
  - `POST /` — разбор JSON, валидация по контракту выше, honeypot (`hp` непустой → отвечаем
    `{"ok":true}` и молча выбрасываем: бот не должен понять, что пойман);
  - лимит в памяти: не больше 5 отправок с одного IP (`X-Real-IP`) за 10 минут → `err:"rate"`;
  - `sendMessage` без `parse_mode` — игрок может написать `<`, `&`, `*`, и любой parse_mode
    превратит это в 400 от Telegram (грабли из `docs/TELEGRAM_BOT.md` проекта spark);
  - `shot` → base64-декод → multipart `sendPhoto` (собрать руками, ~25 строк);
  - `GET /health` → `ok`.
  - Логи: `INFO` на каждый принятый отчёт (kind, длина текста, уровень, есть ли скрин, IP),
    `WARN` на отбраковку с кодом, `ERROR` на ответ Telegram ≠ 200 с телом ответа.
    **Токен не логировать никогда** — ни в URL, ни в тексте ошибки: `urllib` кладёт URL
    в текст исключения, поэтому исключения ловить и печатать только `err.code`/`err.reason`.

- [ ] **T2. `server/pozerkalam-feedback.service`** — systemd unit:
  `EnvironmentFile=/etc/pozerkalam-feedback.env`, `User=www-data`, `Restart=always`,
  `NoNewPrivileges=yes`, `ProtectSystem=strict`, `PrivateTmp=yes`. Файл трекается в git —
  секретов в нём нет, только путь к env-файлу.

- [ ] **T3. nginx.** Два куска:
  - `/etc/nginx/conf.d/pozerkalam-limits.conf` (http-контекст):
    `limit_req_zone $binary_remote_addr zone=fb:1m rate=6r/m;`
  - в `pozerkalam.space` — новый location:
    ```nginx
    location = /api/feedback {
        include snippets/pozerkalam-headers.conf;   # без этой строки серверные заголовки отключатся
        limit_req zone=fb burst=3 nodelay;
        client_max_body_size 1m;
        if ($request_method = OPTIONS) { return 204; }
        add_header Access-Control-Allow-Origin "*" always;
        add_header Access-Control-Allow-Headers "Content-Type" always;
        add_header Access-Control-Max-Age 86400 always;
        proxy_pass http://127.0.0.1:8787/;
        proxy_set_header X-Real-IP $remote_addr;
    }
    ```
    CORS нужен не для `/play/` (там свой origin), а для билда Яндекс Игр и старого зеркала
    194.5.65.182 — они шлют на этот же абсолютный URL с чужого origin.
  Логирование: `nginx -t` перед reload, вывод в консоль деплоя.

### Фаза 2 · Клиент: форма и точки входа

- [ ] **T4. Секция `/* ---------- обратная связь ---------- */` в `index.html`**
  (после секции HUD, до раздела оверлеев — порядок зависимостей: нужны `toast`, `esc`, `track`, `showOv`).

  - `fbSend()` — `fetch` POST, кнопка на время запроса в состоянии «Отправляю…» и `disabled`

  - кулдаун 60 с в `localStorage['trainer_fb_t']` — «отправил и сразу ещё раз» защищает

  - успех → `toast('Отправлено. Спасибо.', 3)` + `track('feedback-sent')`;
  - провал → форма остаётся заполненной, красная строка с причиной и кнопка
    «Скопировать текст» (`navigator.clipboard`, фолбэк — `select()` на textarea).
    Никакой потери написанного: игрок уже потратил на это две минуты.
  - Логи: `console.warn('[fb]', код, ответ)` на каждую неудачу.

- [ ] **T5. Форма `fbHTML()` + маршрутизация в `doAct`.**
  - Поля: три чипа вида отчёта («Что-то сломалось» / «Есть идея» / «Отзыв»), `<textarea>`
    (maxlength 2000, автофокус), `<input>` контакта (maxlength 120), чекбокс
    «Приложить снимок экрана» (включён), скрытое honeypot-поле
    (`style="position:absolute;left:-9999px"`, `tabindex="-1"`, `autocomplete="off"`),
    кнопки «Отправить» и «Отмена».
  - `doAct`: `feedback` (открыть), `fb-send`, `fb-close`.
    **`fb-close` обязан вернуть тот экран, с которого пришли:** при `game.done` физика заморожена,
    и простой `hideOv()` оставит игрока в мёртвом кадре — та же ловушка, что уже описана
    для `doAct('resume')`. Запомнить источник в `fbBack` ('game' | 'win' | 'fail' | 'start' | 'exam').
  - Клавиатура: `typingInField` уже отсекает `keydown` в `INPUT`/`TEXTAREA` — новых правок
    в обработчик не нужно, но проверить, что русская раскладка в textarea не рулит машиной.
  - **Тексты — по `.ai-factory/references/pozerkalam-voice.md`**, прогнать перед коммитом:
    `python3 ~/.claude/skills/ru-copy-deslop/scripts/deslop-scan.py index.html`.
    Ни «геймплей», ни «фидбек», ни «пользователь» — обращение на «ты», как инструктор.

- [ ] **T6. Точки входа** (зависит от T5):
  - **Десктоп:** третья плавающая кнопка `#fbBtn.sidebtn` `top:174px`, текст «✉ написать».
    Гард по геометрии: боковые зеркала начинаются с `sy=clamp(H*0.40,116,…)`, и на низком окне
    они наезжают на кнопку — HTML-кнопка молча съест тап, нацеленный в зеркало на канве
    (та же грабля, из-за которой верх зеркал ограничен 116 px). Прятать `#fbBtn`, когда
    `mirrorRects().right.y < 206`. Скрытие в `compact/hud-off/ov/edit` наследуется от `.sidebtn`.
  - **Телефон:** строка в ≡-меню, блок «Прочее»: `add('✉ Сообщить об ошибке', …)` рядом со
    «Справка и правила». На тач-экране ≡ — и есть экранная кнопка, отдельную вешать некуда.
  - **Стартовый экран** (`startHTML`, обе ветки — MOB и десктоп): ghost-кнопка внизу,
    рядом с «Экранное управление».
  - **Экраны провала и победы** (`levelFailHTML`, `winHTML`, `examFailHTML`): ghost-кнопка
    «Что-то не так — написать». Это момент, когда игрок злее всего и готов написать.
  - Логи: `track('feedback-open:'+источник)` — станет видно, откуда реально пишут.

- [ ] **T7. Скриншот** (зависит от T4):
  снимок берётся с `canvas#view` **в момент нажатия кнопки, до `showOv`** — оверлей ставит

  Логи: `console.warn('[fb] снимок не снялся', e)` — и отправлять отчёт без картинки,
  а не падать: текст ценнее скриншота.
