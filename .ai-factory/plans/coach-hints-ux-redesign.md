## Проблема

Жалоба игрока: «очень много текста, непонятно что за что отвечает, неинтуитивно» для первого захода. Диагноз по коду:

1. **Всё сливается в одну текстовую полосу.** `#coach` — единственная строка, куда 11-веточная цепочка приоритетов (index.html:2919-2934) сваливает всё: отказ селектора, столкновение, toast, goalMiss, лекцию про P/N, фазовую подсказку. Тип сообщения не различим ни цветом, ни формой.
2. **Подсказки — предложения по 60–108 символов**, смешивающие действие + признак завершения + имена клавиш («Руль ВПРАВО до упора и медленно назад — веди, пока «угол к цели» не дойдёт до 45°»). Худшая — L5 (index.html:1178, 108 зн., две стратегии в одной фразе).
3. **Жаргон без объяснения**: «угол к цели» (25 упоминаний), «зазоры» (33), «крип», «доворот», буквы P/R/N/D, клавиши — расшифрованы только в `ctrlHTML()`. Связь «слово в подсказке ↔ цифра в HUD» новичку не видна.
4. **Стартовый экран** — параграф ~2000 знаков про Аккермана и кастор (index.html:3038-3052) — стена текста до первой поездки.
5. **Онбординга на десктопе нет** (touch-туториал `#thelp` есть, index.html:4031-4059).

## Архитектурные решения

- **Структурная карточка вместо строки.** `#coach` получает детей: `#coachIcon` (крупный глиф слева), `#coachMain` (короткое действие), `#coachGoal` (чип цели с живым прогрессом), `#coachWhy` (свёрнутое пояснение) — и класс типа на контейнере: `k-stop` (отказ селектора, красный), `k-hit` (столкновение, оранжевый), `k-info` (toast, серый), `k-almost` (goalMiss, жёлтый), `k-gear` (P/N, синий с паузой), `k-act` (фазовая подсказка, голубой), `k-ok` (готово, зелёный). Ветки цепочки 2919-2934 маппятся на типы; порядок приоритетов НЕ меняется.
- **Данные структурируются в источнике, а не парсингом строк.** `phases[]`-записи расширяются опциональными полями — `phaseTick` (2507-2521) читает только `.when` и передаёт объект целиком, доп. поля безопасны:
  - `icon` — глиф фазы (Unicode, как принятые ⏸/⚠/▶);
  - `act` — короткое действие (цель ≤45 зн., на MOB — ещё короче);
  - `goal` — `{metric:'ang'|'front'|'rear'|'left'|'right', target, dir:'down'|'up'}` для живого чипа; для ориентирных фаз («до голубой линии») — `{text:'…'}` без метрики;
  - `wheel` — `'lockL'|'lockR'|'left'|'right'|'straight'` и `move` — `'fwd'|'rev'|'stop'` для пиктограмм;
  - `why` — развёрнутое пояснение (текущая длинная формулировка переезжает сюда).
  - `hint` остаётся и работает как fallback: карточка без структурных полей рендерит его как `#coachMain` — конвертация уровней инкрементальна, кастомные пады (`genericCoach`) и уровень «Полигон» не ломаются.
- **Чип цели = ответ на «что за что отвечает».** Чип показывает имя метрики, целевое значение и живое текущее («угол → 45° · сейчас 12°» + мини-бар прогресса). Все значения уже считаются в `updateHUD` каждый кадр (угол: 2907-2913; зазоры: `curS.front/rear/left/right`). Тап/клик по чипу пульсирует соответствующую ячейку `#bar` (CSS-анимация по образцу канвас-пульса зеркал, 2680-2689) — связь подсказки с HUD-цифрой становится показываемой, а не описываемой.
- **Пиктограммы**: мини-руль (глиф со стрелкой, CSS `transform:rotate()` по `wheel`), стрелка направления ⬆/⬇, бейдж передачи [R]. Обновление — только по смене значения.
- **Progressive disclosure**: кнопка «?» на карточке (у `#coach` стоит `pointer-events:none`, L37 — кнопке нужен `pointer-events:auto`) + клавиша `Slash` в `pressKey`; раскрывает `why`. Счётчик запусков `trainer_runs`: первые 3 запуска `why` раскрыт автоматически. Лекции P/N и `hitReason()` сокращаются до короткой формы, полное объяснение — в `why`.
- **Онбординг** — по образцу `#thelp`: затемнение, привязанные к живым rect'ам call-out'ы (`getBoundingClientRect`), пауза игры, шаги «Дальше N/5»: карточка подсказки → «угол к цели» (`#angVal`) → зазоры (`#cf..#cr`) → селектор (`#gearVal`/`#tgear`) → поехали. Один тур для десктопа и MOB (разные якоря). Флаг `trainer_seen` (конвенция `trainer_*`, try/catch как везде); срабатывает из `doAct('start')` рядом с существующим гейтом `trainer_hint` (2956-2958).
- **Все DOM-записи — только по изменению** (правило L2876, паттерн `setText`/`gearShown`): рендер карточки кэширует составной ключ `kind|icon|act|goalDef|whyOpen`; живые значения чипа пишутся через `setText`, ширина бара — по изменению округлённого %.

## Констрейнты (нарушение = регрессия)

- Каждая подсказка остаётся парой «действие + видимый признак завершения»; пороги в текстах/чипах равны позициям нарисованных маркеров и порогам демо-сегментов — числа НЕ трогать, только форму.
- `when()`-логика фаз, сенсорная модель, `PHASE_HOLD` — не меняются.
- Ветки приоритетов: selWarn всегда выше toast; префикс P/N не заменяет фазовую подсказку, а предшествует ей (короткая форма: «⏸ P · тормоз + Enter» + `act` фазы).
- CSS-взаимодействия `#coach`: `body.mir` (top:104px), `body.compact` (низ, `--mirbot`), `hud-off`, `edit` — карточка выше строки, проверять перекрытие `#bar` в compact.
- Тексты и комментарии — на русском. Имена клавиш в подсказках унифицировать: всегда «R (Enter)», не «R («.»)».
